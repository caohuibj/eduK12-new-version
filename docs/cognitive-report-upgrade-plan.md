## 1. 升级后的产品效果

学生/家长进入报告后，按顺序获得：

1. 本次记录能解释到什么程度；关键限制直接可见。
2. 一句有数据依据的反馈，说明完成了什么、哪里值得留意。
3. 两到三个容易理解的数字，保留单位、分子和分母。
4. 与任务相匹配的图解，解释真实作答过程。
5. 一个可执行的下一步：熟悉操作、核查环境或在指导下重测。

教师详细解读保留相同的本次事实，并补充已有权限范围内的质量原因、指标定义、协议限制和版本依据。用户已确认本轮仅完善已有权限内的解读；不新增科研专用指标读取入口。

各任务保持共同的配色、文字层级与状态语义，图表和任务示意按任务选择。目标不是创造跨任务能力总分，也不是用漂亮图形掩盖质量限制。

## 4. 新报告契约与数据来源

以下为设计约束；最终字段位置与实际范围见本地交付说明。已新增报告契约版本 2，同时保留现有报告版本读取能力。这里的版本 2 指报告对象，不是把任务引擎或整个 Cognitive runtime 升为 2。

新输出保留必要的兼容字段，并增加：

| 字段 | 内容 | 来源/规则 |
|---|---|---|
| `schemaVersion` / `reportVersion` | 结构版本与内容规则版本 | 新生成报告明确标识；无版本旧报告走旧适配器 |
| `interpretation` | `available / qualified / withheld`、原因码、相关指标 | 冻结的报告解释策略；与原 scorer quality 区分 |
| `caveats` | 首屏限制与方法补充 | 已冻结的协议限制，不临时读取新定义 |
| `feedback` | 本次事实、限度与行动建议，含 evidence metric keys | 任务自己的文案模板、原始指标、质量 flags |
| `visuals` | 图表类型、单位、轴定义、有效记录与缺失状态 | 完成时依据允许的正式试次生成，随结果冻结 |
| 科研专用扩展（本轮排除） | 未新增 `research` 字段或读取入口 | 用户确认只完善已有权限内的解读 |
| `provenance` | 呈现版本、报告规则版本及原配置/协议/评分身份 | 与完成快照一起冻结；现有身份保持可追溯 |

具体 TypeScript 类型已在 CR-01 落定，采用兼容的可选字段；本轮未变更现有结果数据库表结构。若确需迁移，单列方案与迁移验收。

### 解释策略

采用任务自己的、仅用于报告的策略声明，随 participant presentation 或独立 display sidecar 冻结。显示策略不进入刺激、计时或评分定义；优先复用现有质量 flags，不新造未经验证的阈值。

- `available`：足够记录且目标指标允许解释，描述本次事实。
- `qualified`：存在中断等限制，显示允许的记录并同步限制，避免比较性结论。
- `withheld`：目标指标所需记录不足、缺失或不可解释，撤下该指标的个人主结论；完成数量等过程信息可以保留。
- 全局 invalid：原有禁止解释与参考披露行为继续生效。
- 指标局部受限：可以限制 SSRT 而保留允许的 go 条件记录；不把一个不足标记自动扩散到所有指标。
- 未知原因码：采用保守、可理解的提示，不能把技术旗标自动翻译成注意力差、冲动或其他人格结论。

若选用现有 `requiresQualityFlags` 修改执行元数据，必须先确认编译/冻结 hash 是否变化，并按相应语义版本处理。首批优先用冻结的报告策略，避免为显示修复更改运行时契约。

### 生成、读取与权限

新任务发布/冻结时保存报告策略和呈现版本 → 完成时用相同冻结内容生成完整新报告 → 结果快照保存 → 读取 API 按现有归属与 disclosure 权限输出允许的阅读层 → 前端只显示已经获准的数据。

教师解读切换不是授权动作。科研协议也不是读取科研内容的充分授权。当前没有独立个人结果读取权限的角色不因这次升级自动获得权限；匿名公开任务同样不能取得研究层或其他用户原始试次。

新图表优先使用简单 SVG，保留可读文字摘要。试次数较多时采用明确标注的分箱或采样显示，算法/参数冻结，核心数字仍来自完整评分结果。不支持某种图表数据时显示文字摘要，不能用前端臆造阶段或缺失记录。

## 5. 三项样板的产品要求

### reaction

首屏：有效反应数量，典型用时，以及未及时响应/提前操作。中位数显示为“典型反应用时”，解释其含义。变异系数放教师层，说明不是正确率。

图表：逐试次散点；未响应置于单独事件带，不占用纵轴用时，不填 0。早按是事件计数，可能与有效试次重叠。

验收样例：20/18 有效 → 310 ms；20/5 有效 → 主结论暂缓，不突出 305 ms；20/0 → 无速度结论；18 有效但 interrupted → 限制可见，不能默认为正常可比较结果。前三个数字依据此前真实评分器执行的模拟数据。

### SST

首屏先说明协议限制，再解释允许的 go/stop 作答过程。SSRT 必须满足适用的解释门控；停止响应概率有目标范围，不用“越低越好”的颜色或标签。

教师层列出估计方法、stop 有效记录与限制。短程协议不形成个人抑制能力结论；标准协议与科研协议也不产生临床分数。图表只采用真实可获得的条件或延迟数据。

### memory

首屏说明本次正确完成到多长的数字序列，以及尝试结果；如果测到配置上限，明确“达到本任务上限”，不暗示已测得个人真实上限。

图表：长度与作答成功/失败阶梯；缺失与错误区分。顺背与倒背分开解释。现有 suppressTips 的意图先核查，仅增加有依据的操作/阅读提示，不简单开启所有旧训练建议。

## 6. 全任务覆盖顺序

每项检查：三类协议、有效/局部受限/不足/无有效记录、学生/教师授权、文案证据、图表单位与缺失、并存评分身份、旧冻结快照。

| 阶段 | 家族 | 图表方向与重点 |
|---|---|---|
| 样板 | reaction、sst、memory | 时序缺失、条件门控、跨度阶梯 |
| 第一轮其余 | stroop、gonogo、cpt、nback、corsi、taskswitch | 条件速度/准确率；不同分母；按 N 分层；空间序列 |
| 第二轮速度/干扰/切换 | patterncompare、flanker、cardsort、lexicaldecision | 速度与正确率权衡、条件差值、命中/误报 |
| 第二轮记忆/推理/规划 | digitbackward、picturesequence、pairedassociate、wordlist、matrix、mentalrotation、tower、trailmaking | 真正测量的阶段与难度，过程/步数，避免 IQ 或临床标签 |
| 第二轮学习/决策/面孔 | reversallearning、bart、emotionrecognition | 概率阶段、兑现与爆炸轨迹、合成面孔类别限制 |

BART 优先采用可创建的 1.1.0 身份，旧 1.0.0 作为兼容身份单独审查，不原地覆盖。全部 24 个家族都在列表中；fake 只承担契约测试。

正式上线范围以目标实例只读导出的 `CognitiveTestConfig.status` 确认，不能用本云 seed 状态代替实际发布清单。这不阻塞本地开发。

## 7. 文案与视觉交付标准

每项任务保存一份文案表：标题、指标浅白名、解释、状态反馈、行动建议、教师说明，以及各句子的 evidence keys 和禁止解释。模板采用确定规则，不用无依据的即时生成结论。

统一主体深蓝、行动蓝、低饱和青绿及灰色背景；琥珀表达解释限制。状态同时有文字和符号。沿用现有 token，认知专属排版用限定容器，避免修改全局 CSS 导致量表/综合报告回归。

每项 2–3 个首屏指标；细节有明确入口。图表必须标单位、分母/范围、缺失规则；不同单位不拼雷达或标准化能力总分。图表旁有文字摘要，手机图轴仍可读，键盘可操作，打印保留核心限制与版本。

已有[学生样稿](assets/cognitive-report-upgrade/report-proposal.png)、[教师样稿](assets/cognitive-report-upgrade/report-proposal-teacher.png)、[不足状态](assets/cognitive-report-upgrade/report-proposal-insufficient.png)及[交互稿](assets/cognitive-report-upgrade/report-proposal.html)作为视觉和信息顺序起点，图稿数据为模拟，实施不得把样例数字写进业务模板。

## 8. 版本与历史结果策略

- 纯文案更新：升级 presentationVersion，新任务冻结新内容；历史冻结显示保持其依据。
- 新解释策略/报告字段：升级报告契约和规则版本，并冻结策略；score 和原质量数据不变。
- 评分数学/刺激/协议变化：对应新的 scoring/engine/config 身份，另列任务。
- 已完成结果：读取存量结果快照，不能因新代码自动用实时定义重新投影。
- 已发布但未完成的旧 assignment：按其冻结的报告版本和策略完成；缺少新字段时用旧路径，不能默认为新策略。
- 旧快照缺少可证明的图表依据：退回文字，不用实时原始数据补画后声称是原报告。

历史报告的 P0 问题需要另行治理：允许采用单独有版本的“阅读提醒”附层，明确原报告版本与新提醒版本，保留旧数字与原始快照；涉及重新生成时必须有可追溯记录、发布范围与验证，不能静默替换。CR-02 先完成兼容和风险提示设计，不默认批量改写历史结果。

## 9. 验证与交付门槛

| 验证层 | 必须验证的真实边界 |
|---|---|
| 单项报告 | 不足数据不给个人主结论，局部门控与其他允许指标独立；低正确率不自动等于技术无效 |
| 冻结与版本 | 修改实时文案/策略不改变旧冻结结果；新/旧报告解析均正常；编译/runtime hash 在仅呈现改动中不变 |
| 完成与重复提交 | 新字段真实持久化；历史读取及幂等提交读到相同冻结报告 |
| 权限 | 无权限角色响应中根本没有科研/原始 trial 数据；已有 cohort-only 限制继续有效 |
| 文案 | 每个事实句绑定实际数据；分母、单位、缺失、协议上限一致；禁用未经验证的常模/诊断标签 |
| UI | 学生与教师层、四种质量状态、手机与桌面、键盘和打印；共用 primitives 的相关报告回归 |
| 合入时 | 更新后主线上的类型/构建、契约、相关集成/E2E；远端当前 CI 与保护要求按最终 SHA 完成 |

按风险运行现有检查并补充必要的边界测试，不为单纯换文案添加镜像实现的测试。已有 43 项 review 检查属于旧基线证据，不替代后续实现验收。

本地交付包：提交清单、基线与头 SHA、变更文件、各工作单状态、版本说明、测试摘要、前后截图、已知限制、回退路径。回退采用撤销独立实现提交/恢复前端兼容读法；不撤销或重写已经保存的新报告数据。旧客户端兼容必须在合入前明确。

## 10. main clean 后的对齐与合入

收到用户明确 clean 信号后：

1. 读取最新 origin/main，记录 SHA；将本地提交与主线比较，检查本轮涉及的契约、权限、共享 CSS、冻结路径是否变化。
2. 在本地工作分支对齐最新主线。专用本地提交可 rebase；已发布分支不得随意重写。存在冲突时逐项检查语义，不只消除冲突标记。
3. 运行变更相关检查和必要回归，生成最终差异与结果清单。测试未通过则继续本地修复。
4. push 专用分支并创建可审阅 PR，以此触发仓库当前配置的 CI。单独 push 工作分支未必触发当前 CI，因此不能仅 push 后声称已触发。
5. 检查最终提交 SHA 对应的必需 CI、审批与分支保护；不绕过失败、取消、缺失或过时的状态。
6. 通过后 merge；如果 base 或 head 又变化，重做受影响验证并遵循最新保护要求；主线合入后确认 post-merge smoke。

当前主线 CI 对内容/呈现/平台改动有不同路由。新报告投影/冻结/权限属于平台变更，不能因为有文案或 CSS 就把整批归类为纯展示以省略后端验证。方案不修改 CI 配置。
