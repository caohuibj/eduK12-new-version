## Reuse and behavior

`group-longitudinal.ts` assembles already disclosed `TaskGroupProjection` values, retains null/zero/signed deltas and actual completion ranges, and requires actual Cognitive protocol plus consistent units. It does not calculate a second mean/SD, score instruments, use current norms, or infer improvement/significance. Report/reference provenance changes do not gate the raw comparison; publishing and existing leaf readers preserve the frozen measurement identity. Stable plan metric IDs resolve the current leaf position before score keys are extracted.

Survey reuses `loadSurveyItemDictionary/loadSurveySource`, `surveyGroupFacts` and `summarizeGroupMetrics`. It selects the latest whole completed parent by scoped identity before quality filtering, using one source cutoff. Training reuses the existing source catalog/reader, latest-parent policy, governance and `trainingGroupDisclosure`. Their single-wave generators are factored to return a transient prepared projection; existing single-wave storage/output shapes remain unchanged. Existing ownership and teacher/manager route checks remain authoritative.

The existing encrypted `reporting_task_artifacts` store receives only `report_kind/plan_id` and an index. Single and longitudinal histories have separate lists/reads. A generated version stores aggregate output and original source pointers once; reads recheck current authority/inclusion and original hashes without rescoring/decrypting participant FINALs. A withdrawn/excluded original source can make its old aggregate unavailable; the saved snapshot itself is not overwritten. No second result database, queue, permissions platform or reporting engine is introduced.

Shared manager UI selects a planned leaf and final published wave, explicitly generates an update, opens saved versions and reuses `ReportTrendChart`. The table retains valid/missing/completed counts with existing suppression and count units; mobile columns scroll instead of compressing Chinese labels. The initial browser harness does not include the whole product shell/Tailwind; its role is the real shared component + authorized HTTP/PG journey, not a full-site navigation claim.
