## Implementation

`nativeGroupSource.ts` is a thin identity/content adapter. After the existing actual Teacher product-admin / event / Run guard, it accepts only explicitly published Teacher native SELF GROUP 2.0.0. Existing `readEducationAssessmentDeliveryIdentity` verifies the released parent, frozen runtime slot, immutable C/P/R and original publication proofs. The adapter binds the requested canonical leaf to the exact C instrument identity (Cognitive runner/engine version, not configVersion), then returns that unit's own groupDisclosure. A current-epoch completed UNIT_RESULT header verifies the supplied compiledRuntimeHash without decoding canonical results on snapshot reads.

Existing Teacher numeric source discovery/generation/Artifact read/UI and the existing group engine are reused. The comparable-disclosure query resolves native C measurementHash through the frozen item's origin, so parent containers do not become independent disclosure identities. Published metric and participant contracts, existing floors, missing-complement and actual-contributor guards remain. Old native 1.0.0 and unrelated source families remain rejected. No role, permission, table or second statistics/scoring system is introduced. No School namespace or Long-owned pagination is edited.

The shared native publisher had a concrete group-registration bug: its snapshot construction inserted an undefined educationBinding when a native C source had no private education binding. Omit that optional field instead. Existing bindings have identical values; this does not synthesize a binding or change an old frozen version.

## Limits

The parent is an ordinary native mixed composite containing COG and SJT, not a Bundle-product Profile analysis acceptance case. This is one reaction experience protocol and one installed SJT source; it does not claim acceptance of every cognitive protocol or scientific validity. Source creation/approval and test authentication are explicit synthetic fixtures in the isolated loopback database. Actual Teacher runtime guards, FINAL persistence, canonical engines, source adapter, aggregation and saved reads are unmocked in the PG journey. Specs use the existing platform API/lifecycle; no new automatic publishing or native content-management UI is introduced. Full browser/PDF, old Scale journeys, original/group-contract suites and full CI were not repeated. No external writes, merge, deployment, production or permission-setting changes were attempted for this slice; all existing denied external operations remain stopped.
