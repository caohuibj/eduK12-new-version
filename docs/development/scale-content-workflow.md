# 标准量表导入与优化

本规则在 #831 架构合并并部署后执行。第一次安装需要部署包含量表渲染器与配图清单的前端、共享发布后端和可运行内容同步的 ops 镜像，并按运维入口初始化专用发布身份。[发布操作手册](../release/operations.md)

## 优化已登记量表

1. 核对题目、选项、计分和适用条件。确认无误就沿用题本 C。阈值变化新增 `parameters/<P>.json`，报告变化新增 `reports/<R>.json`。仅改报告可绑定现有 P。R 必须与选定 P 的分档匹配，并明确四类受众各自可见的内容。一般先处理现有上线量表，再补齐具备上线条件的候选。
2. 核实来源、译本、实际使用及配图许可。阈值标明依据和证据等级。初步估算明确标注试用。按任务约定把审阅稿放到 Google Drive，可将链接写入 `reviewNote`。许可等真实卡点未解决时保留草稿。清单里的 `readiness` 仅用于说明准备情况。
3. 经内容审阅确认后，在 `releases.json` 新增 `ONLINE` 声明，指定精确 C/P/R、题本摘要和实际适用的入口。若指定 `replaces`，历史键仍保留在同一清单内，必要时标为 `WITHDRAWN`。首个 Git 版本可用 `<C>/default` 引用已登记的旧版，该引用不会撤销既有人工管理的版本或授权。已发布的 P/R 文件保留原件。
4. 从 `server-version/backend` 运行 `npm run scale:check -- <toolKey>`，或把它作为纯内容 CI 的主要检查。它校验结构、版本和分档映射、配图引用、替代链及三份代表性试算。样例取各题首、中、末选项，分档边界与证据仍需按需核对。输出的 `[]` 表示没有本次发布声明。通过结果确认内容包对样例可运行。来源、许可、阈值证据及报告表达由审阅确认。纯内容 PR 已由 GitHub 承担正式检查时，本地用于编辑定位和审稿。本地结果当前没有正式内容 CI 接纳入口。
5. 仅含 P/R 和 `releases.json` 的声明变更走 `scale_intake_light`，复用应用镜像。合入主干并取得当次上线指令后，用已获取的官方 `origin/main` 精确提交同步，保留版本、就绪和回退核对。

```bash
bash "$U" content --entry "$ENTRY" --ops-overlay "$OPS" --scale-main-sha "$MAIN_SHA" --apply
```

**新增静态图**。在 `server-version/frontend/src/scale-report-artwork/<toolKey>/<C>/<artVer>/` 增加 `report-artwork.json` 和 WebP，先交付并更新包含这些图的前端产物，再同步量表声明。配图内容改变时使用新标识，保留旧图。静态配图无论单独提交还是与声明一起提交，目前走 C 类 CI。生产只需切换受影响的前端产物，后续可引用已部署的配图标识并走轻量内容检查。部署使用 `update.sh frontend` 切换后，再单独用 `update.sh content --scale-main-sha` 同步。确有跨组件或迁移需求时才使用受控的 `full`，可在切换后由同一命令同步声明。

## 导入全新量表

| 用途 | 做法 |
| --- | --- |
| 平台标准量表，后续持续批量维护 | 在量表目录新增 `1.0.0/source.json` 和 `instrument.ts`，登记题本、计分、适用性和 `dataCeiling`。运行 `npm run scale:instruments:generate` 更新注册表，准备 P/R 和清单。核对 `npm run scale:instruments:check` 与 `scale:check` 对应结果。首次发布要有包含新 C 的合格 backend/ops 产物。内容 CI 不产出这些镜像，镜像单独按现有资格入口准备。只有服务镜像变更时可用 `service --scale-main-sha`，需要迁移或跨组件时按 `full` 手册执行。有新配图时加上前端产物。以后的 P/R 更新沿用上面的内容流程。 |
| 后台导入并由管理员维护 | 总管理员在「批量导入与草稿」下载标准 Excel 模板，预览并保存有效草稿。上传入口使用 Excel，每批最多 10 份、2 MiB。JSON 可用于草稿编辑或现有结构化草稿 API。核对精确组合、报告受众和允许的入口，完成近期双因素验证后发布。三份自动试算与回读通过后上线。此类数据库题本后续从已冻结组合创建新草稿，按需升 P/R。已有后台附件和前端静态配图分别使用现有素材引用和已部署的配图标识。 |

## 上线、授权与回退

- 两条路径上线时只开启明确选择的入口。具体学校、教师或研究者的使用权沿用现有对象级授权流程。
- 回退时调整清单，或由管理员撤下组合，保留已发布 P/R 文件。如果上一版仍声明为 ONLINE，撤下替代版可使上一版恢复。需要停止所有新增使用时，明确撤下所有仍在用的相关组合。
- 已入场的被试始终沿用原来冻结的版本完成作答和提交。校验集中在审阅、发布和入口准入，被试端沿用现有查询流程。
