# 四入口工具授权统一开发方案

本地实施基线为 main `8280c788f`。Training、Survey、School 和 Teacher 共用商业许可管理、有效期、额度、续期和终止流程，各自沿用产品准入和业务角色规则。下述实现及验证记录对应本轮本地候选。

## 当前实现范围

总管理员可在「系统管理 → 管理授权 → 工具授权」管理四个入口的许可，从已上线的共享治理工具跳转时自动带入工具。撤下的工具仍可查覆盖它的历史许可。签发时可选择指定工具或跨页加入该入口全部当前可授权工具，自定义起止时刻，也可用半年和一年快捷填写。列表可筛选待生效、有效、30 天内到期、已到期和已终止。续期展示工具增减和额度变化。终止前回读本期工具、已计量发布数和教育预留状态，再确认影响。School、Teacher 展示「本校可用工具」，Training、Survey 工具库展示「我的工具授权」，可按实际记录核对期限、额度、发布接入和精确配置分配状态。 [总管理员工作台](../../server-version/frontend/src/admin/AdminToolLicenses.tsx) · [入口许可状态卡](../../server-version/frontend/src/components/tool-licensing/OwnToolLicense.tsx)

标准量表上线后可「去分配」，School、Teacher 从组合详情按学校和管理员名称选择，确认实际覆盖组合及期限，可选择限当前精确组合或覆盖同一测量版本的获准组合。详情可查和撤销，管理员详情可反向查看分发记录和受影响的下游固定配置。交接时可先给合格接任人签发同范围委托，由接任人按需重发固定配置，再撤销原委托。Training、Survey 的固定版本分配入口带入具体发布版本，由具备对应入口资格的管理员沿用现有分配流程。 [量表分配工作台](../../server-version/frontend/src/pages/admin/StandardDelegationPanel.tsx) · [管理员交接](../../server-version/frontend/src/admin/StandardDelegationReviewPanel.tsx) · [Training／Survey 固定版本分配](../../server-version/frontend/src/pages/admin/StandardEntryAssignmentLinks.tsx)

| 入口 | 已接入的正式发布边界 |
| --- | --- |
| Training | 正式发布课程或通用问卷时，每项符合来源条件的标准量表、共用库量表、固定认知配置及平台 SJT 计一次。可兼容原生投放的治理公共表单和纯表单普通组合使用对应的公共工具计次。课程独立量表按已冻结的适格来源计次，独立固定认知任务从自身发布入口计次。合格原生组合包按整包计一次。 |
| Survey | 研究者第一次正式开放冻结波次时，覆盖已批准的标准量表、共用库量表、治理表单、认知测评、SJT、普通组合和组合包，以及可投放的原生精确认知配置。治理整包只计父工具。 |
| School、Teacher | 发布教育普通组合时，按固定标准量表、共用量表、公共表单、认知与 SJT 的实际覆盖名额预留。同一工具在同一轨道出现多次只预留一份名额。已接入的原生组合包按整包预留。已登记的独立认知和 SJT 使用获准的精确来源计量，共用库独立量表按固定版本及来源摘要识别。Teacher 学生评教使用获准公共表单组成的投放，在正式发布时校验截止和原生作答上限。截止须在许可期内，上限须与冻结名额一致。 |

学校和教师试点的未用额度由后台按工具关联的轨道退回原期次。结算读取既有执行及入场记录，允许截止前已开始的入场事务完成后再核算，只锁商业额度账本。首次入场、刷新、续答、暂存、提交及报告继续沿用现有链路。

扩展校验由各入口的 `<PRODUCT>_TOOL_LICENSING_ENABLED` 控制，原标准量表试点开关可继续独立使用。开关默认关闭。首次建立许可期次前，发布沿用现有规则。私有自建内容、缺少对应入口获准精确来源的历史认知配置、未登记的原生包和预览型教育治理包继续沿用各自现有路径。开通前按入口和工具核对目录标识及真实发布能力。

## 统一标签与批量签发

School、Teacher、Training 和 Survey 的正式入口管理员可编辑本入口可授权公共工具的标签，总管理员可在统一授权工作台维护四入口标签。标签在入口内按稳定工具身份保存，支持添加、移除和按完整标签筛选。私有自建工具也可在自己的编制空间添加、删除及回读标签，沿用作者、项目或学校表单的管理权限。私有标签不进入公共授权目录，保存标签不修改内容、草稿修订或冻结版本。

总管理员先选产品，多选符合资格的学校或业务账号，再按标签选择指定工具，或一次加入该标签在本入口当下匹配的全部可授权工具。每批最多 50 个对象和 2,000 项对象与工具分配。预览展示实际对象、工具、逐项额度、起止时间和重叠冲突。确认时重新核对范围，任一对象不能签发时整批不写入。重试同一批次读取原始回执。签发记录保存确认后的具体工具范围，后续调整标签只影响下一次筛选。签发继续使用原有许可账本，作答路径不读取标签或批次。 [标签管理](../../server-version/backend/src/modules/tool-licensing/tags.ts) · [批量签发](../../server-version/backend/src/modules/tool-licensing/batch.ts)

## 产品决策

总管理员按**产品入口和授权对象**开通工具许可，选择工具范围并指定到期时间。School 和 Teacher 按学校开通，Training 按具备资格的培训师账号开通，Survey 按具备资格的研究者账号开通。总管理员可立即开通或指定开始时间，也可为个别工具增设可选使用额度。许可归属于学校或获授权账号，签发或分发人员的交接按独立管理流程办理。

覆盖量表、表单、认知测评、情境判断测验（SJT）、普通组合和带独立报告的组合包。各类型使用同一授权流程。某个工具能否进入学校目录、能否发布任务，仍取决于其所在入口已获批准且具备对应运行能力。

**商业授权和次数只在正式发布时校验。** 授权到期或提前终止后，停止新的发布。已发布任务继续按原冻结版本、任务有效期与既有作答规则执行。首次入场、恢复、暂存、提交和报告分别沿用现有流程，商业授权零额外查询、零新增门禁。平台版本撤下和已有紧急停用规则分别沿用各自的治理流程。

## 总管理员的操作流程

主入口设在「系统管理 → 管理授权 → 工具授权」。在同一工作台按产品搜索授权对象，按对象或工具过滤许可记录。找到学校后可打开该学校在所选入口的许可详情。获准的共享治理工具可从详情跳转到许可工作台并预先带入工具。

1. **选产品和授权对象。** School、Teacher 按校名搜索并核对学校和对应产品是否开通。Training、Survey 按名称或账号查询，只允许选择具备对应业务资格的人员，并显示同名账号的识别信息。切换产品或授权对象时清除依赖旧范围的工具选择。
2. **选授权范围。** 支持「指定工具」与「全部当前可授权工具」两种方式。按名称和类型检索，显示用途、可用入口与当前可用版本。已有资料但尚未准入、已撤下或缺少运行适配的工具，显示原因并禁止加入。确认页列出实际覆盖的工具。
3. **填写期限和可选额度。** 默认立即生效，也可选择未来的开始时间。「自定义到期时间」可直接填写具体日期和时刻。「半年」和「一年」用于从开始时间快捷填入到期时间，填入后可以继续修改。每个工具可选「不限次数」或填写本期最多使用次数，默认不限次数。提交前展示授权对象、产品、工具清单、已设额度、准确的到期时刻及所在时区，并沿用现有二次认证、变更原因和审计。
4. **管理已开通的权限。** 在授权列表按产品、学校、账号、工具、类型与状态筛选，直接续期、调整工具范围或提前终止。需要核对精确配置时，按入口查看业务侧授权卡和工具目录。

学校工作台展示「本校可用工具」，Training 和 Survey 工作台展示「我的工具授权」。缺少业务资格、入口未批准或尚待分配精确配置时，页面显示具体原因和办理入口。UUID、来源摘要及授权修订在详情中供审计或排查。

### 范围与期限的首期默认规则

| 项目 | 规则 |
| --- | --- |
| 指定工具 | 以目录中的稳定工具标识选取。操作员可在许可范围内选用入口已批准且可运行的精确版本。新版本上线后，可以用于新的任务。旧任务保持原版本。 |
| 全部当前可授权工具 | 签发时保存该产品当时可用的工具清单。未来新增的独立工具须由总管理员显式加入。页面显示实际清单与工具数。 |
| 续期 | 支持提前安排下一期，默认沿用原工具清单，由总管理员确认。连续续期保持新使用连续。有空档时，新使用在空档中停止。续期不重新开放已经关闭或过期的任务。 |
| 期限边界 | 授权可指定任意有效的起止时间，结束时刻须晚于开始时刻。采用开始时刻包含、结束时刻不包含的时间区间。「半年」和「一年」分别按所选业务时区加六个月和一个日历年，统一显示可编辑的准确结果。 |
| 工具使用额度 | 每个授权对象、产品、授权期次和工具独立设置，默认不限次数。Training 和 Survey 按成功正式发布计次。School 和 Teacher 按每次发布确定的作答上限预留额度，到期结算并退回未使用部分。额度与期限只影响新的发布。 |
| 入口范围独立 | 同一学校的 School 和 Teacher 授权各自生效。Training 和 Survey 分别绑定已核对的业务账号。同名人员或关联身份的授权按签发记录生效。 |
| 终止整笔与调整部分 | 「提前终止」停止该对象在该入口的本期工具许可。「移除工具」只影响本期被移除的工具。确认面板说明具体影响，授权和作答历史均留存。 |

商业许可按工具系列管理，可覆盖入口批准的同一工具多个版本。标准量表精确组合委托和入口固定版本分配负责具体版本的分发范围。单个任务始终在发布时选定精确版本。合同如需把商业额度本身锁定到某个版本，须单独确定计量口径后再实施。

| 平台工具治理 | 总管理员 | 维护标准或共用工具的来源和版本，完成该类型规定的审核、试运行和入口批准。版本变更形成新发布。 |
| 工具许可 | 总管理员 | 对指定学校或具名业务账号开通入口、工具范围、期限及可选额度。处理续期、移除工具和提前终止。 |
| 入口管理与业务资格 | 对应入口管理员和校内人员治理流程 | 管理培训师、研究者、School 心理教师、Teacher 校内产品管理员等资格。继续通过现有入口办理需要精确配置的分配。 |
| 活动与作答 | 有资格的业务作者和已入场的参与者 | 作者选用许可内的精确版本发布活动。参与者按本次入场冻结的任务继续作答。 |

工具许可决定授权对象能用哪些平台工具。当前业务资格、产品开通、平台批准和工具原有来源授权共同决定具体操作。Training、Survey 已有标准固定配置或共用库使用权时，通过既有授权记录保留版本和来源。入口授权卡会显示已有精确分配、待入口管理员分配或需到目录核对；量表上线详情到 Training、Survey 分配管理页时带入精确版本，人员由有权限的入口管理员核对。个人私有草稿按既有归属和发布规则管理，进入平台共用范围继续走现有审核。

## 管理端和运行端的实现

### 统一授权记录与管理接口

统一授权记录以「授权对象类型、对象标识、产品入口」确定归属。对象可以是学校或具名业务账号，按产品限制可用类型。记录期次、起止时刻、覆盖工具清单、各工具可选额度、当前修订、变更理由及操作者，保留续期、范围调整、额度变更和终止的审计。同一对象和入口可有一笔有效授权及已安排的后续期次，期次不得重叠。历史记录保留签发时的工具标识、名称快照与实际范围。

复用现有组织、账号资格、产品开通、工具目录和入口批准机制。学校产品开通记录只表达开通或暂停。Teacher 的校级量表许可以及 Training、Survey 的固定配置使用权可作为兼容来源，目前这些记录没有统一的期限和额度。带起止时间的个人精确分发委托继续用于入口管理。商业许可、入口分发和具体工具的冻结配置各自保留原始责任和使用依据。 [学校产品开通模型](../../server-version/backend/prisma/schema.prisma#L3392) · [Teacher 校级量表许可](../../server-version/backend/src/modules/huiteacher/scaleLicense.service.ts#L123) · [Training 标准量表使用权](../../server-version/backend/src/modules/measurement-content/standard-combination-use.ts#L55) · [Survey 标准量表授权](../../server-version/backend/src/modules/survey/catalog.service.ts#L71)

总管理员侧需要受现有管理权限保护的学校、合格业务账号与可授权工具查询，以及授权的列表、详情、签发、调整、续期和终止。列表能按授权对象、产品、工具和有效状态定位。保存时重新核对对象资格、产品范围、工具批准与修订，重试同一请求时读取原结果，避免重复签发。并发变更按现有版本校验模式处理。

### 授权查验与冻结

新增的许可判断只接入正式发布事务。管理端的目录和预览可批量显示可用状态。正式发布从学校任务、课程或研究项目解析许可对象，校验有效期和额度，将已确认的版本及额度写入发布记录。Training 和 Survey 的额度分别归对应培训师和研究者。School 与 Teacher 使用发布时已冻结的任务截止和可执行名单或原生名额设置。授权状态、余额与退款均由发布端或管理后台处理。

| 时点 | 行为 |
| --- | --- |
| 编辑草稿或查看目录 | 显示当前工具权限、受阻原因和期限。保留草稿与历史浏览。 |
| 正式发布活动、问卷或首次开放一个发布版本 | 核验对应学校、培训师或研究者的工具许可和既有发布条件，扣减或预留并记录授权依据。发布失败或回滚时额度同时回滚。确认同一发布结果的重试沿用原记录。 |
| 第一次真实入场 | 沿用现有任务的名单、截止与原生名额逻辑。沿用发布时冻结的配置和既有任务限制，作答请求不查询商业许可、商业授权到期时间、已用次数或剩余次数。 |
| 刷新、找回或重试已入场的作答 | 先按原入口识别并恢复已存在的入场与作答。使用其冻结版本、既有身份凭证和原完成期限。 |
| 暂存、交卷、计分和生成原报告 | 沿用冻结定义、原身份规则和幂等路径。授权到期或人员交接不会成为这些环节的新查询或验证门槛。 |

商业授权在发布事务内以当前时间判断有效性。到期、提前终止和范围调整保留审计记录，并停止受影响范围的新发布。产品暂停、账号处置和已有紧急停用规则走各自的治理流程。 [既有作答恢复边界](../../server-version/backend/src/modules/assessment-run/startExecution.ts#L295) · [Survey 现有版本准入规则](../../server-version/backend/src/modules/survey/tool-policy.ts#L44)

### 可选工具使用额度和并发要求

- **Training 和 Survey 按成功发布扣次。** 一个正式发布对使用的每个独立工具计一次，重复引用同一工具去重。获许可的整包按整包计一次。预览、草稿、暂停后恢复原发布及重试同一发布均不重复扣减。
- **School 和 Teacher 按发布人数上限预留。** 发布必须明确任务截止时间和正整数作答上限。截止不得晚于本次涉及的每份许可到期时间，上限不得超过每项有限额工具的当前剩余额度。整包按包预留，多个独立工具分别预留。优先复用现有冻结名单或任务原生名额，发布时保证上限已落入现有任务约束。无法沿用原生人数约束的发布面应先明确固定分配范围，才开通该额度功能。
- **到期退回未用额度。** 以任务已到期且原任务不会再新增有效作答为结算前提，后台从已有作答记录读取已实际入场的人次。实际入场的作答已占用名额，即使其稍后完成提交也不释放这笔额度。将预留减去实际占用后的差额退回原授权期次并留审计。结算可重试，重复结算不会多退，也不会把已经到期的许可重新变为有效。
- **发布原子性。** 额度按授权对象、产品、期次和工具独立记录。按不可变的发布标识和工具记录去重，扣减或预留随发布成功提交。持锁区间只处理授权、额度和发布落库，并发发布不得超扣。学校活动发布后若要扩大人数或延长有效期，走新的发布审核边界重新核对许可及额度。
- **作答热路径零增加。** 对首次入场、刷新恢复、暂存、交卷及计分均不新增商业授权 SQL、Redis 调用或即时门禁。退款计算、提醒和用量统计在后台执行。以相同数据和负载对照原始作答路径，验收查询数、吞吐、P95/P99 及锁与连接等待。并发争抢余额、发布回滚、重复发布和退回幂等在发布端与后台单独验证。

### 四入口的上线兼容

四个入口都接入统一授权。首期 School、Teacher 按学校管理，Training、Survey 按具名业务账号管理。后续若需要让学校合同同时覆盖 Training 或 Survey，可扩展明确且可审计的学校与业务账号、任务归属关系。机构扩展与本期的 Training、Survey 账号授权分别验收。 [共用库产品与组织授权边界](../../server-version/backend/src/modules/scale-library-governance/contracts.ts)

为已开通学校和已有培训师、研究者授权保留兼容路径，核对原有对象、产品、范围和期限后按产品与对象逐批切换。对已切换对象的受管工具，旧人员授权与已有来源绑定继续表达原有资格或版本依据，新许可的范围和期限同时生效。发布前对比切换前后的可用工具，验证旧作答可继续和历史数据可读。回退保留已发许可的审计与已冻结作答。已明确终止的授权需要经过明确的授予流程才能重新生效。

## 分阶段交付与验收标准

| 阶段 | 交付范围 | 验收重点 |
| --- | --- | --- |
| 一　四入口统一管理端与授权模型 | 以产品与对象检索学校、培训师和研究者。支持签发、查询、续期、终止、指定到期时间及半年和一年快捷填写。 | 四入口均可选择合格对象，无需手填 UUID。可按自定到期时间开通指定工具或全部当前工具，确认页与回读一致。 |
| 二　四入口发布接入 | 用统一许可判断接入 School、Teacher 校内活动，Training 独立量表、课程问卷与组合，以及 Survey 波次发布。额度随发布事务扣减或预留，教育活动到期在后台结算。 | 四入口验证发布校验和失败回滚。教育活动验证截止、人数上限和到期退回。涵盖首入场与提交的作答路径查询数保持基线。 |
| 三　续期与交接运营 | 到期提示、续期与范围变更对照、管理员交接视图。按实际业务量决定批量操作及 Training、Survey 的组织购买扩展。 | 资格交接与许可记录可单独回读。便捷查询受影响的配置与用户，历史签发责任完整。 |

以下是完整验收标准。每个入口接入新工具类型时，使用对应场景验收总管理员和入口账号在浏览器授权、发任务和回读。后台验证到期结算，参与者实际经过首次入场、刷新和续作。普通平台撤下与商业授权到期采用各自验收用例。

| 场景 | 预期 |
| --- | --- |
| A 校按自定日期开通，B 校用半年快捷填写后仅选两个工具 | 两校分别按确认的时刻和范围生效。快捷填写后的到期时间可编辑。交叉访问及授予未批准资源失败。 |
| 同一学校仅开通 School 工具 | Teacher 返回明确的产品范围原因。仍要求 School 对应岗位和专业资格。 |
| Training 培训师获两项工具的许可 | 在有效期和额度内成功发布时扣次。超范围或到期后的新发布被拒。已经发布的任务按原作答规则运行。 |
| Survey 研究者获指定工具的许可 | 首次正式开放已冻结的波次发布时扣次。预览、失败回滚、原版本恢复及被试的入场、刷新和作答均不扣次。 |
| 同名或关联业务账号跨入口选工具 | Training 许可只对签发的培训师账号和 Training 生效，Survey 许可只对签发的研究者账号和 Survey 生效。身份搜索、签发和实际投放的权限结果一致。 |
| 生效前、到期边界及提前终止 | 在时间边界上准确拦截新发布，其他有效授权和已经发布的任务沿用自身规则。 |
| 授权到月底，教育活动尝试发布到下个月 | 发布被拒。修改到授权截止以内后才能发布。 |
| 教育活动的冻结名单拟产生 300 个作答名额，剩余 250 次 | 发布被拒。若调整名单后产生 200 个作答名额，重新预览并确认即可预留 200。已有任务的作答规则沿用原冻结快照。 |
| 预留 300 次，活动到期前实际入场 220 人 | 后台仅退回 80 次，同一个到期结算重复执行仍只退 80。未完成但已入场的人数计入 220。 |
| 同时发布争抢剩余额度、发布失败或回执丢失 | 成功发布扣减总数不超过余额。失败不扣，重复请求回读同一发布结果。 |
| 作答热路径基线对照 | 首次入场、续作和提交的查询数保持原基线，零新增商业 Redis 调用和门禁，吞吐及尾延迟无可重复退化。 |
| 续期与调整清单 | 续期覆盖确认后的范围。被移除工具停止新增使用。旧任务冻结版本和答卷保持原记录。 |
| 授权期内更换管理员 | 接任者按现有角色办理，学校许可、范围和截止日期继续生效。原账号的管理权限按交接操作结束。 |
| 组合包中含学校未单独购买的组件 | 按已授权整包及其固定定义正常使用。试图把组件作为独立工具发布时，必须有相应独立授权。 |
| 平台撤下已获学校许可的版本 | 新任务和新入场继续按平台撤下规则处理。已入场恢复、交卷及历史报告维持原冻结链路。 |

发布时按实际变更选择门禁。只验证受影响的管理与运行链路，输入一致且可核验的证据按仓库已支持的方式复用。学校授权兼容切换、到期边界与回退作为实际变更的验收条件。 [发布规则](../release/README.md)
