## 实施前设计核对

实际核对管理权限矩阵 `docs/admin-permissions/README.md` 和当前的组织访问、产品授权、显式 deny、School MFA、注册 admission、学生准入、人员邀请及班级关系服务。

- 平台系统角色、产品管理授权、学校成员身份是不同维度。批量人员接口要求当前有效 SCHOOL 账号、ACTIVE 学校、HUISCHOOL entitlement、当前学校 ORG_ADMIN 和 School PRODUCT_ADMIN，不能仅凭业务 `User.role=ADMIN`、系统身份或 COUNSELOR 放行。管理名单不等于读取心理报告。
- 导入、名单读取、激活码发放、核实已有账号均经最近五分钟 School MFA；沿用 `/api/campus` 的来源、CSRF、认证保护。已有账号本人确认不提升其管理资格，不代学校做整班审批。
- 旧 `replaceCampusRoster` 是替换入口，不能用于只新增导入。导入后它明确拒绝再替换该班名单。旧的纯学号手工注册方式继续适用于未使用新导入的班级。
- 班级 OPEN、APPROVED 或已有注册时不能新增学生；用户再次确认本轮保留该锁定，不做已审批班级补录／转班／升年级。
- School 与 Teacher 共用教育身份，心理准入独立。新增身份使用同一学号摘要的并发锁，若该学号已有教育账号则要求原账号本人确认，不能新建第二个账号。Teacher 仅在其学生激活服务接入该共用身份保护，不修改界面、产品权限或心理审批。
- 旧学生激活码是班级级别，不保证绑定某个学号。导入人员使用绑定本人资格的凭据；原通用码不能激活导入学号。教师导入凭据固定不带 adminRole/psychologyStaff。

## 输入与工作流

入口：学校管理员 → 学校与班级 → 人员名单。CSV／TSV／多行表格粘贴，UTF-8、含表头，每批 1–100 行、最大 64 KB。页面提供模板。大名单分批明确确认；不会后台自动重试。

| 名单 | 必填 | 选填 |
|---|---|---|
| 学生 | 学号、年级、班级 | 姓名、已有校园用户名 |
| 教师 | 工号／固定人员编号、姓名 | 身份（默认普通教师）、已有校园用户名 |
| 任教关系 | 工号、年级、班级 | 任教角色（班主任／任课教师；默认任课教师） |

同一文件只属于当前学校。编号保留字符串及前导零，按现有规则规范为大写；不接受身份证、电话、密码或任意管理权限。年级／班级按校内精确名称唯一匹配，未知／重名均拒绝，不创建结构。

预览不写数据库。确认时服务器重新检查内容、解析目标和当前权限，并与预览 HMAC 比较。在一个 PostgreSQL 事务内写入整批人员／待生效关系／资格及审计；任何失败整批回滚。批次 UUID + 内容 HMAC 支持同一请求重放；编号、已有账号及关系唯一约束是数据库最后防线。并发冲突要求重新预览，不静默重试。

同编号同信息跳过；冲突报错。空的可选姓名不会清空旧姓名，不同非空姓名不会覆盖。不同编号即使同名也不合并。遗漏人员／关系不删除、结束、冻结或转班。教师可以有多个任教班级；关联已激活教师时追加已有授权范围内关系，未激活时等本人激活生效，不创建心理个案关系。

学生名单新增会保留班内此前所有未注册资格，同时更新待注册名册修订，使旧未用班级激活码失效。导入本身不创建 User、membership、STUDENT persona 或 APPROVED enrollment。学校单独发放个人码、开启窗口，学生自行设置用户名和密码，之后仍由独立心理教师整班审批。

导入教师本人设置账号后仅有 MEMBER 和明确普通业务 persona；COUNSELOR persona 不带 PSYCHOLOGY_STAFF 或任何报告能力。管理／专业授权仍走原受控流程。

已有校园用户名需管理员线下核实并明确确认；系统只登记预期账号，不能替本人激活。忘填用户名时可对尚未绑定、未激活记录执行一次单独的“核实已有账号”；不能改已有绑定、姓名、编号、班级、密码或权限。旧码同时撤销，重新发放后由本人在“我的账号 → 激活名单身份”确认。已有 School enrollment 不重复注册；已有 Teacher 学生保留原身份并申请独立 School 准入。

## 数据保护与运行

新增四张 SQL-owned 表：campus_personnel、campus_personnel_import_batches、campus_personnel_assignments、campus_personnel_credentials，均列入 runtime-table-policy。只增加结构，不回填旧账号或授权。

学号复用现有 HMAC；工号及批次指纹用分用途 HMAC。名单原编号、姓名、可选用户名以 AES-256-GCM 加密，AAD 绑定学校和人员 ID；加密/比对密钥从现有 CAMPUS_ELIGIBILITY_HMAC_KEY 按不同用途派生，不写入源码或新增默认密钥。该既有密钥及密文必须按现有备份约定一并保护，不能直接轮换丢弃旧密钥。原测评、任务与报告投影不接收名单姓名。

个人激活码数据库只存既有摘要，界面仅显示本次返回值，不存 localStorage／日志／审计；重新发放撤销旧绑定。激活时复查发码人的当前学校权限及发码后的撤权，撤销后恢复不能复活旧凭据。导入审计仅含种类和计数，不含名单原文。

本地验证在新建、空白结构的独立 PostgreSQL test 数据库执行，不用现有手动验收数据库。未推送、未启动远端 CI、未部署；正式发布仍需按完整实际差异分类，不能把本轮本地结果称为已接入正式 CI 的资格。
