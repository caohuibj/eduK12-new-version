# P1-C02 observation contract

The existing `ptool_assessment_phase_duration_seconds` histogram reports **inclusive** time for each named phase. Nested phases overlap and their sums must never be treated as total latency. The existing `response` residual uses the union of phase intervals, while `ptool_slow_requests_total` assigns each timeline slice to one exclusive dominant phase on slow requests. These are distinct interpretations.

New bounded phase names are `sjt.validation_index`, `snapshot.parse_hash`, `cognitive.frozen_report_db`, `cognitive.frozen_report_decrypt`, and `response.build`. SJT parent finalization reuses `final_submit_parent_finalization`; other aggregate phases already use the `aggregate.*` namespace. `sjt.validation_index` currently covers the per-answer validation and index build together, so it is the comparable baseline for P2-C02. `response.build` for SJT includes stored-result decoding. Phase labels remain enum-constrained and carry no payload or account ID.

`ptool_prisma_call_duration_seconds_count` counts **logical Prisma middleware calls**. `ptool_prisma_sql_events_total` counts process-wide Prisma query events only when both `PERF_ISOLATED_TEST_MODE=1` and `PERF_SQL_EVENT_COUNT=1` are set at process startup. It has no route labels and is not a network round-trip count. The collector records event duration but never SQL text or parameters. It is disabled by default. Run it only on an isolated test instance. A real isolated PostgreSQL `SELECT 1` probe produced exactly one SQL event and no SQL text in metrics.

The `/metrics` scrape performs one read-only `pg_stat_activity` sample. `ptool_pg_database_connections`, `ptool_pg_database_active_connections` and `ptool_pg_database_lock_waiters` describe **all client backends for the current database**, including the scrape; they are neither this API process's Prisma pool occupancy nor the Prisma client wait queue. `ptool_pg_activity_available=0` means the sample failed, in which case the counts are omitted. Pool wait remains unobserved directly and must not be inferred as zero.

`process_cpu_seconds_total` is cumulative CPU across the process; CPU deltas across concurrent requests cannot be assigned to one request. RSS and heap gauges are omitted when memory collection fails, never populated with zero. Existing ELU and bounded gate active/queue/rejection metrics are preserved. The local no-scrape vs 5-second scrape comparison is stored under `server-version/perf/current-main-v1/evidence/observer-effect-20260923/`; it probes `/ready` on a developer host and does not qualify FINAL throughput or whole-host capacity.
