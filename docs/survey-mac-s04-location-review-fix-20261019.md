Form 的 `answers.<key>` 现在定位到 `survey-preview-<key>` 试答 fieldset；`pages.<index>.questions.<index>` 仍定位到 `survey-form-<key>` 编制 article。定位按钮继续使用原生 button，Enter 可触发。缺项与无效数值用例先填写第一题的有效回答，再分别提交缺少／非法的第二题；点击问题后不会把焦点送回编制区，不修改答案、不调用计分或 PATCH。

导入位置不再把所有 `issue.line` 当成物理行。现有响应没有统一 origin 字段，因此前端只识别当前后端已核对的错误来源，未知消息保守显示“无法确定精确行”，不提供假精确跳转：

- CSV 解析器／行校验的已知错误使用实际物理行，明确标注“源文件第 N 行”。表头仅对明确的表头错误允许第 1 行。
- Scale 的“指定的量表维度不存在”来自应用阶段的条目序号；同时核对该序号条目的 dimensionKey、实际不存在的维度与返回的 sourceLine，再映射到输入记录。带引号换行的记录按 sourceLine 与下一记录边界选择，不加一猜测。
- 一般 apply 错误、未知消息、缺少上下文、无法核对的行编号或 TEXT 中语义不明的编号均不宣称精确行。技术细节显示原始“服务端位置编号（不保证为物理行）”。后端未来改变消息或缺失 sourceLine 时会退回不可精确定位，不扩大错误语义。
