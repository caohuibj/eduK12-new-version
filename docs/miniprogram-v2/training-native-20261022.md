# Training 原生学员端：第一批实现

基线为 GitHub main `61bb4cc1534fcb02869b27973794001021826de0`，本地分支
`work/training-miniprogram-native-20261022`。目标目录为
`server-version/miniprogram-v2`；旧 `miniprogram` 不改。

本批修改组件为原生入口、账户适配、课程列表/详情和课程测评入口；检查用于发现
身份串用、分页丢失、课程越界、归档作答误开新轮次、迟到响应或图片残留。
主要执行位置是独立 Mac 工作区，复用未修改的提交、封存草稿、计分及后端权限协议。
执行预算约 30 分钟，检查为秒级定向 Node 用例与静态检查；不包含平台 CI、
Web 构建、数据库变更、生产访问或微信真机验收。不复用旧 Web CI 为本批资格。

## 已实现

- 实际 App 启用 `studentOnly`。登录使用 `/auth/training-login` 并固定
  `expectedRole=STUDENT`；恢复会话仅接受 LEGACY/TRAINING 学员和一致的
  mobile discovery。其他身份清理本地会话及草稿，服务器仍负责签发与核权。
- 注册只开放学员；删去教师、家长、组织、课堂和公开参与的页面注册及服务初始化。
  通用 v2 基础模块保留兼容能力，但实际 App 不初始化其他角色的工作区。
- 首页直接展示本人课程，无全局导航；只有零课程时展示三步入门引导。
  支持课程码加入、账号资料、游标续页、去重、失败保留已加载课程和刷新竞态保护。
- 课程内提供练习、打卡、测评栏目，任务详情保留课程上下文，提交复用现有
  原生 operation 页面及后端 revision/commandKey。本人记录展示提交文字、题目
  答案、评语和经认证下载的打卡图片，迟到图片与页面卸载会清理临时文件。
- 测评列表覆盖问卷、量表、认知测评和组合测评；多课程投放逐页核对课程任务。
  单类读取失败显示明确提示，其他已加载项仍可使用。
- 测评投影直接从 Training Web 的 `courseAssessments.ts` 生成，生成脚本校验
  完整输出和源摘要。保留归档后本人可继续/查看反馈、暂停、截止、任务达成等语义。
  继续时传递已有 rootId，不另开 attempt；实际恢复、提交与反馈再次由后端核权。
- 原生作答只在服务器 `canUseAssessmentRuntime` 开放时显示开始按钮，不私开开关。
  不改冻结版本、观看完成门槛、计分、次数、披露策略或截止时间规则。

使用本环境已固定的 Node 24.21.0，不新增依赖。

- `node scripts/check.cjs`：82 个 JS 模块、16 个注册页面、组件/WXML/设计 token/
  传输边界检查通过；不是微信编译结果。
- `node scripts/sync-training-assessments.cjs --check`：生成投影完整字节核对通过。
- `node --test tests/training-student.test.cjs`：当前 19 个用例全部通过，覆盖身份、
  课程核权、分页竞态、归档继续、部分失败、本人反馈和临时图片清理。
- 6 个直接兼容用例通过：实际详情错误恢复、App 前台刷新、环境分离、发布配置
  拒绝、上传源排除与既有封面选择返回。
- 初次选择的五份定向文件运行 139 个用例，138 通过、1 失败。该失败是新测试
  用 assert.rejects 接收同步抛错；改为 assert.throws 后相关 6 个身份用例通过，
  后续增加的 3 个用例及当前 19 个集合通过。原 139 次调用保留失败身份，不声称
  那次整条命令通过。未重跑输入未变的 operation/assessment 提交检查。

这些为合成 API 和原生页面生命周期单测，不冒称微信运行或真实后端端到端验收。
