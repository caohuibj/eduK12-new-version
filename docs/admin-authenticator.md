# 管理员 Authenticator 绑定与登录

管理员可使用微软 Authenticator、Google Authenticator 等标准 TOTP 验证器。
登录仍需要账号密码和动态码；验证器不会授予系统管理员或产品入口权限。
已登记的独立 WebAuthn 安全密钥继续可用，可在绑定、登录及敏感操作页面选择。

## 新管理员如何加入

1. 首位系统管理员由受控后台的 `CREATE_SYSTEM_ADMIN` 创建。后续入口管理员可以使用
   已有的 Legacy/Training 账号，由系统管理员明确授予所需入口权限。网页不能自行注册或
   提升为系统管理员；Survey 研究者账号也不能通过绑定管理员验证器升级为管理员。
2. 受控后台使用 `ISSUE_ENROLLMENT` 为已有管理账号签发一次性绑定票据。新建账号时
   同样会签发票据。票据十五分钟有效，写入新的绝对路径私有交接文件（0600），不在
   标准输出中打印；密码通过 stdin 传入，不写命令参数、日志、Git 或公共分享。
3. 管理员打开 `/admin/security/enroll`，默认选择“Authenticator 动态码”，输入账号、
   当前密码和登记票据，点击“生成绑定二维码”。二维码最多五分钟有效，且不能超过票据
   剩余时间。微软 Authenticator 中选择“添加账号 → 其他账号”扫描二维码，再在网页
   输入六位动态码并确认。扫码密钥仅在当前页面展示，不存浏览器本地存储。
4. 绑定成功后不自动登录。等待手机动态码更新，在 `/admin/login` 输入密码和新动态码。
   仅通过密码校验的挑战不能访问管理员接口。
5. 系统管理员进入 `/admin/permissions` 为账号授予需要的入口权限，例如 `SURVEY`。
   系统管理员身份本身不代替入口授权。授权变更会使相关账号旧会话失效，需重新登录。
   Survey 研究者随后通过原有邀请与自己的 TOTP 绑定流程加入。

本轮保持受控后台签发绑定票据，未新增网页自助邀请管理员的功能。

## 敏感操作和恢复

管理会话最长八小时；敏感授权、撤权等操作仍要求最近五分钟的管理员双因素证明。
页面提供新的 Authenticator 动态码验证，也保留已登记安全密钥验证。相同时间步的码
不能再次使用，包括刚确认绑定或刚登录所用的码；需要时等待下一次动态码更新。

已绑定的 Authenticator 不能用另一张登记票据直接覆盖。丢失设备时使用原有受控
`RECOVER` 操作：保留账号和权限，提升 tokenVersion 使旧会话失效，删除旧的 TOTP
凭据、硬件密钥和挑战，再签发新的短期绑定票据。真实账号恢复仍需当次授权，不能
通过关闭 MFA、手工伪造会话或直接写授权表代替。`ISSUE_ENROLLMENT` 也会使旧会话
及待验证挑战失效，但不删除现有认证器。

## 配置、数据和兼容

- `ADMIN_AUTH_ORIGIN` 指定受信任的管理员来源；兼容旧 `ADMIN_WEBAUTHN_ORIGIN`。
  生产仅支持现行 Training 管理来源，本机开发可使用明确的 localhost 来源。
- `ADMIN_MFA_ENCRYPTION_KEY` 为独立的 32 字节十六进制 AES-GCM 密钥。不能复用 Survey、
  JWT 或业务加密密钥。绑定后须保留对应密钥用于解密，不能直接更换。Compose 只向 API
  注入该密钥，不向 worker、迁移或 seed 容器注入。密钥缺失或解密失败时拒绝操作。
- 迁移 `20261022040000_admin_authenticator_totp` 新增 `admin_totp_credentials`，扩展已有
  挑战用途约束，不修改已有硬件密钥、用户权限或业务数据。运行角色策略明确分类新表。
- TOTP 使用 SHA-1、六位数字和三十秒时间步，允许前后一个时间步的时钟偏差。密钥使用
  AES-256-GCM 加密，AAD 绑定账号与管理员域，不能跨账号或跨产品复制密文。
- 一次性挑战由 HttpOnly / SameSite=Strict Cookie 绑定，校验当前账号域、活跃状态、
  权限和 tokenVersion。数据库行锁串行化确认及时间步消费，错误码也消费挑战。
  Redis 按服务端挑战对应账号限制十五分钟最多二十次动态码校验，并保留独立 IP 限制；
  Redis 或身份查询不可用时拒绝验证。CSRF、来源检查及敏感操作会话绑定继续生效。
- 原硬件密钥账号无需重新登记；选择“已登记的安全密钥”继续使用。未绑定验证器的账号
  不会降级为密码登录。研究者与校园原有 TOTP 凭据及绑定协议未修改。

## 本地验证范围

本轮使用独立 Mac 工作区及合成 PostgreSQL/Redis/API，运行当前新增及直接受影响的
认证、页面、恢复、硬件兼容、重放和撤权检查。类型检查、变化文件 lint 和真实页面
显示单独记录。报告在仓库外保留，不提交测试账号、二维码、Cookies、原始票据、
加密密钥或数据库备份。未运行全量测试、正式 CI、镜像扫描或生产部署；这些本地
结果不代表正式发布资格，也不声称已完成用户手机扫码和完整 Survey 人工验收。
