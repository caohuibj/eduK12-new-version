# Cognitive 发布报告只读盘点与验收

本流程区分“代码支持新版报告”和“指定部署的发布任务使用新版冻结策略”。盘点工具只读配置和任务，不读取参与者、session 或原始作答，不写入数据库、不重算、不补写冻结快照。

## 运行盘点

在 backend 目录、已配置目标数据库及现有 cognitive 加密密钥的环境运行：

```bash
npm run cognitive:reports:audit -- --scope-label <明确的数据库范围> --output /tmp/cognitive-report-inventory.json
```

`--scope-label` 必填，报告含数据库范围、时间、配置目录、发布任务身份、冻结呈现/报告版本、分类和建议。不要将密钥或数据库连接串写入命令、报告或 Git。输出可能含任务名称和配置 ID，按维护资料保存；CLI 输出文件权限为 0600。

自动门槛可额外加 `--fail-on-pending`。只有 `FROZEN_POLICY_COVERED` 返回成功；空目录、待复核或只有综合流程均不会假装通过。该状态只表示冻结策略覆盖，不能代替正式浏览器验收。

## 分类与处理

| 分类 | 含义与下一步 |
| --- | --- |
| current_two_audiences | 精确任务身份和当前双报告冻结版本匹配；验证完整提交、个体回读及归属教师回读。 |
| historical_reading | 发布时冻结的是历史呈现；保留原报告。如需新版，为后续作答创建并发布新任务。 |
| missing_snapshot | 没有版本化报告快照；保留已有授权阅读/导出入口，核查发布来源。不得用当前规则静默填补。 |
| unreadable_snapshot | 快照不可读或身份不一致；核查完整性与密钥，不修改原结果、不自动回退重算。 |
| unsupported_identity | 精确注册身份不受支持；核查版本，不替换成同类测验的其他版本。 |
| original_composite_flow | 原综合/群体流程继续使用原有权威报告与权限，单独验收；不转换为单测个体报告。 |

本地测试数据库输出为 `NO_PUBLISHED_ASSIGNMENTS`：12 配置、0 发布任务。这是环境实况，不能推断远端发布覆盖。

## 发布阶段验收

本地修复阶段用户要求“先不 push，不触发 CI”；随后在 2026-10-01 明确授权推送与 CI。按最新 [工作约定](cognitive-report-upgrade-working-agreement.md) 整合 main 并验证后推送。目标部署的发布目录盘点与新业务任务发布仍按独立生命周期和相应授权执行：

1. 对齐最新 main，检测差异与冲突，按实际变化运行必要回归；再按用户授权 push、CI 与合入。
2. 对目标部署执行只读盘点，保存带范围标识的报告；逐项处置旧冻结或缺失快照，保留历史记录。
3. 如需新版，沿现有生命周期为后续作答创建、预览并发布新任务。该工具没有批量升级命令。
4. 使用授权测试账户验证真实完整提交、冻结结果回读、退出重进、教师归属与禁止越权、记录分页与切换。
5. 对个体和后台报告截图、打印：匿名/报告标识、完成时间、任务名可见，质量受限时不披露 withheld 指标；展开细节可打印；320/390px 无溢出，Matrix 无格子重叠。
6. 保留部署版本、任务冻结版本、盘点结果及截图。异常时停止新任务发布，原历史结果仍按原快照读取；不通过重算历史结果修复展示问题。
