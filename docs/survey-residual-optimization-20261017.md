# Survey 剩余三项冗余：本地修复与实测

基线 `7620f27e0ab06db6792ae7dbb63edf94bfe43eb7`；代码提交 `e857ce5be42ab50bc63dfd48605da99e60faafbc`；分支 `local/survey-optimized-measured-20261017`。仅当前云端本地 Git，没有 push、PR、main 合并、部署或生产配置修改。历史修复、既有合成夹具和冻结仓库 40c7b273 保留。

## 结论

1. FINAL 新建和幂等重放不再从数据库返回未使用的结果密文。保留全部现有事务外/内校验、锁、撤回检查和 payloadHash/submissionId 一致性检查。
2. Raw 分析按本次请求的已验证 Publication 建立不可变静态描述，只构建一次选项/提示。缺失原因建立保留首条语义的索引；矩阵行优先级和父题回退不变。字典遍历一次，不构造不使用的选项。
3. Score 导出每个输入身份仍进行 canonical 校验，随后复用列 ID；每列只生成最终 codebook，保留原始插入顺序与最后一条元数据优先行为。没有跨请求缓存、评分/输出/schema/安全策略修改。
4. 确证收益是内部返回字节减少、静态重复工作减少和 Score 纯序列化加速。HTTP 延迟没有稳定改善，部分无观察器样本更慢；不能将源码计数下降等同于线上响应时间改善。

## 同输入验证与实验边界

Node 24.21.0、PostgreSQL 17.11、Redis 8.0.2、UTC。单一运行拥有者、单请求并发，既有原生隔离合成库，后台重任务关闭、compact=false。基线复用上一轮已核验 candidate-dist，相关编译文件及 compiler/dependency/config 哈希核对；新候选 TypeScript 编译一次。没有 Docker、浏览器绕过或生产访问。
HTTP：24 或 240 SCALE 题 + 17 FORM 题；匿名、非 Flow、ALL_AT_ONCE。每个比较共享同一冻结问卷；分析夹具有20份FINAL。带计数观察器ABBA，再无观察器ABBA；每块1首样本单列，6暖样本。每变体/场景12暖样本，配对取相应AB/BA块相同序号，均为一个HTTP请求。448次计时请求全部完成；字典和all-items各112份响应，每类按24/240题两个夹具各保存1份基准，其余110份逐一与对应基准做JSON字节比较，全部相同。首样本不是全机器冷启动。
观察器只记录调用数、选中列名、Prisma返回对象的字段/JSON长度、CPU、SQL事件和内存，不记录SQL参数、答案或凭证。纯导出随后单独串行执行；24种组合、12个交替ABBA/BAAB循环、3次预热，计数与计时分开。
