# 教育管理员内部管理层

本阶段新增内部 source/报告预览/接收者/原授权回读和自身精确 use 撤销服务。尚未挂路由或管理员 UI；后续路由继续沿用现有 education 平台管理端的当前密码与最近安全验证，不能把内部服务资格测试称为这些 HTTP 保护已验收。

管理目录只读来源头、已批准本入口范围及本人本校的精确分发委托；当前组织/产品、M、原生安装和 source 状态决定是否可新增使用。自己的历史发行仍可见以便回读和撤销，不能借此重获新增使用权。报告预览取原批准组合，既不读取被试数据，也不重新选择 latest。

接收者投影复用 `organization/educationProductAccess.ts` 原有单人资格 SQL：School 的 COUNSELOR + PSYCHOLOGY_STAFF 与 Teacher 的本校 productAdmin 分别应用，保留当前账号、学校、产品、成员期限及 deny 谓词。批量模式显式由内部 candidatePage 选择且必有学校；空的单人 actor 不会转成批量。原单人导出签名不变，八次虚拟 Prisma 调用（六个不同查询变体）的原/新 SQL 与参数等价；没有改 Bundle 引擎或 Task2 合同。分页候选只作提示，保存仍调用原单人资格解析器。

新的撤销只允许当前匹配入口 manager 撤销自己原先发行的精确学校/source use。系统管理员不从这条入口冒充发行者；既有系统治理撤销 API 保留。原委托或 source 已撤回仍可清理自己的 use，不要求让原件重新 ONLINE。完整 requestId 意图对比、行锁与修订检查防止两条并发撤销把对方的成功冒认为自身请求；T1 审计和配置不改写。

实际通过：12 个权限单测、4 个只读 PostgreSQL 管理场景、4 个独立克隆库撤销场景，涵盖原委托已撤回、完整重试、并发两请求一成功一冲突、source 正式撤回后的撤销与历史回读。受影响后端/测试闭包类型检查退出 0；首轮新查询缺结果类型的编译错误已修正，没有改变运行语义。原八演员库未写入，撤销和 source 状态变化只发生在专用克隆库。证据见相邻 verification.json。

尚缺管理端 HTTP/页面、旧数据 dry-run、同环境性能、Survey 和认知接线及正式 CI。fun 注册的特定权限阻碍未绕过，仍未声称四入口完成或生产可用。
