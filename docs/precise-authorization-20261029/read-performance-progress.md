# 同环境读取成本与 main 的可比较边界

对照基线为 main `dc0f46ba506d51d42c5bb379059df82f18860b72`，候选为
`baad15031f6cca352ec2e8fd7f407bd246a78ae3`。只增加显式启用的探测脚本，未修改业务、数据库、依赖或安全配置。
精确命令、原失败、逐次样本、来源文件 hash 见 [raw](read-performance-raw.json)，数值与限制见
[verification](read-performance-verification.json)。均为本节点实际观测，不是正式 CI 接纳证明。

## 目录：相同对象的 A/B/B/A

两份源码在独立 Node 24.21.0 进程内，复用锁定依赖和同一个 localhost PG16.15 数据库，
以真实受限 `precise_task1_runtime` 身份读取。每组先记录一次首次调用、三次预热，再单并发采样 30 次。
两边都返回同两条合法精确组合；剔除本次新增元数据后的业务投影 hash 完全相同。

| 顺序 | 源码 | p50 ms | p95 ms | DB 查询/次 | 响应字节 |
| --- | --- | ---: | ---: | ---: | ---: |
| A1 | main | 16.82 | 21.19 | 20 | 963 |
| B1 | 候选 | 20.04 | 23.39 | 20 | 1755 |
| B2 | 候选 | 19.97 | 28.71 | 20 | 1755 |
| A2 | main | 13.73 | 17.52 | 20 | 963 |

本次目录新增应用查询为 **0**；既有逐组合权限检查成本仍存在，不能将这两项结果外推成大目录无 N+1。
候选增加 792 字节固定配置业务名、状态和轻量指针，中位耗时约增加 3–6ms。
SQL 事件中位累计时长分别为 4/5/6/4ms；该观测尚不能独立归因于查询、hash 校验或宿主调度。
组间 p95 有明显波动，保留逐次样本和 MAD，不套用生硬 10% 门禁。
规范中的 START/报告热路径目标也不能由这项目录试验代替。

## 报告：main 不具备相同输入的成功基线

最初 main 探测在报告 HTTP 返回 `409 CONTENT_TRAINING_FINAL_IDENTITY_MISMATCH`，
原失败完整保留；没有修改 FINAL、快照或授权去制造成功。随后只读回查的九张表 hash 与失败前相同。
main 能读旧格式，不代表能理解本任务新精确绑定生成的 FINAL，因此这份报告不能作有效 A/B 比较。
该边界也要求回退只切换新建入口，保留已生成新格式的兼容读取器；不能声称整个旧二进制可透明回滚。

候选自身同一份已完成 full-R 报告 30 次热读均成功，p50 **57.11ms**、p95 **90.52ms**，
固定 30 次查询、3714 响应字节；首次调用 242.57ms 单独记录。
这不是相对 main 的 10% 目标通过证明。新旧授权仍分别为冻结修订 7 / 当前物理修订 9，报告未换定义。

五组成功探测均前后核对九张相关表，0 条写语句被观察到，未重新授权、START 或 FINAL。
这些是共享 **255 迁移**数据库上的函数和局部 HTTP 路由试验；main 预期 253 迁移，
没有启动 main 完整 release，也没有把它宣称为 main 启动/迁移资格。
