# 教育入口显式授权替换 lineage

基于 `736ebfdb4585805d3d513c0ccf2af19aec043a7b`，本阶段复用原精确 use 发行事务，不新增表、引擎、入口角色或种子注册。四入口完成状态仍以各阶段证据为准，本阶段只处理 School/Teacher 的共同授权服务及页面。

公共可选输入扩展，供后续各入口接入审阅：

```ts
// 原 requestId/userId/组合/精确委托/期限/名称保持原义。
replaces?: { grantId: string; expectedVersion: number; reason: string }
// 新 T1 审计保存原完整轻量身份；不复制旧报告或重新解释原组合。
supersedes?: { selectedBinding: SelectedConfigurationPointer; reason: string }
```

只有本人为同一接收者、学校、入口和同一工具发行的可信原精确 use 可以替换。新来源、管理资格、接收者资格、精确委托、入口范围和机械执行条件仍完整校验；旧 use 只作为原修订身份和减权目标，不以当前默认版本回填，也不把旧委托失效当成新权限。原版本必须未撤销且与 expectedVersion 相同；无法证明的 legacy 不会被这条路径自动升级。

在原数据库事务中锁定原 use，创建新授权 ID/原精确配置，记录 supersedes 和替换事件，再按既有普通撤权字段将旧 use 版本推进并撤销。旧 T1 metadata 不覆盖，原草稿/已冻结版本不改；新 requestId 不复用旧 ID。幂等完整意图包含原 grant/revision/reason：同原请求可在旧 use 已撤销后回读新结果，换原因或旧修订拒绝。并发两请求只允许一个替换成功，失败方不能留下多余授权。

管理页面从自己的发行历史进入“以新配置替换”，明确说明旧授权将撤销，旧草稿不会跟新。管理员手选已批准新组合、保留原接收者并填写原因。名单重新核当前接收资格，不能改成另一人；取消替换恢复普通新建。未知结果保留原 replaces 完整意图，恢复同时比较旧 grant ID、旧修订和原因。回读历史显示原授权指针及原因。页面不提供未经批准的 C/P/R 编排。

实际独立验证：

- PostgreSQL 4 PASS：原无反馈 R 的真实冻结版本与单独等待草稿；错误入口/修订/自身请求/注入无写入；同 C/P 改为已有完整 R 的原子替换、完整回读/重试；旧等待草稿不能用新 use 自动冻结，原冻结内容保持可读；新明确配置可正常冻结；两请求竞争一成功一 409，只有一条新 grant。所有原来源快照保持不变，旧 T1 实际逐字段比较不变。
- 实际受保护 HTTP 2 PASS：经原 Cookie/CSRF/origin/当前密码/近期 proof/限流路由提交替换、回读两份历史和 supersedes；完整请求重试不新增 grant，变化原因/已失效旧修订拒绝，注入 lineage 400。限流未改，独立 Redis DB3 合成命名空间；原负向中间件证据未重跑。JWT proof 为 fixture，不声称真人 MFA。
- 前端 16 PASS：原 7 个页面场景与新增 3 个替换场景、API 原 4 和新增 2 个完整意图场景。覆盖不同 R、原因必填、保留原接收者、失去资格时不可另换人、未知结果的原替换意图校对，兼容普通创建/撤销和学校切换。
- 最终前后端闭包类型及相关 lint 均退出 0。首轮类型检查只发现新测试未缩窄 ISSUE/null 返回联合类型，原日志保留；补显式分支后通过。四个 PG 场景中的原 request.replaces 相等断言已经实际通过，未为这个测试类型修正重放该库操作。

数据库均从保留的跨 R 合成 fixture 克隆，原 fixture 未写入。只使用已支持的完整 R 与 none-v1，不取用被拒的 fun seed 工程，不重复内容/计分验收。实际参与者 START/续答/报告未在此新跑，普通撤权兼容沿用前阶段证据。正式 CI、代表性能、可信 legacy dry-run、Training/Survey 替换及 T2 显式更换绑定审计仍待后续；这里不声称全任务完成、main 已合并或生产可用。
