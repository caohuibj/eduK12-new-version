# 教育管理员 HTTP、页面及跨报告目录

本阶段在 `015757093f6e720f94159ad0db7aba10d01e219c` 后继续独立开发，未合入 main。School 与 Teacher 共用原 education 平台路由：保留 Cookie/CSRF、平台 origin、最近管理员验证、当前密码及原 Redis 限流；分别映射 HUISCHOOL→SCHOOL、HUITEACHER→TEACHER。读取不缓存，接收者仍为当前本校心理教师或本校 productAdmin；原精确分发委托与入口资格分别校验。

管理员页面挂在既有学校产品管理页，选择已批准的精确组合和本校分发依据、合法接收者、业务配置名称及期限，可读报告说明与原发行历史并撤销自己的 use。系统委托页面同时说明正式平台 manager 的资格；没有让系统审批自动变成使用权。页面目前选择已批准组合，尚未提供任意 C/P/R 的组合编排或原授权的原子替换。

未知写入结果保留原完整意图与 requestId，先从本人的本校/来源操作审计回读。回读匹配完整接收者、配置、委托、修订、期限或撤销原因，才确认成功；无记录时只允许原编号原参数重试。切换学校/产品隔离 pending，请求晚到不写进新页面。管理员密码只在本次发送中使用，不进入 sessionStorage、数据库配置或证据。源/原委托撤回后仍可读本人的历史操作；失去当前入口管理资格仍拒绝读取。

自审发现：原目录仅在一个 combination 内检查名称，两个不同 R 或不同来源页面的同工具同名授权可能误显示成可直接使用。现增加一次最多 129 条的同工具 peer 查询，并共用一次原委托校验批量查询；无逐卡读取、报告编译或 latest 选择。两条同名/未命名配置显示管理员处理提示；源未安装的具体提示优先保留。超过 128 条明确不可选，不能降为 legacy。目录读法改变，发布/START 对原 selectedBinding 的校验未放宽。

实际证据：

- 两次真实 HTTP 执行共 6 个场景通过：Teacher 4、随后 School 2。验证当前密码、近期 proof、CSRF、入口/学校/来源边界、完整幂等回读及正常撤销；Teacher 在原限流额度内恰好 15 次请求，未降低限流或冲洗计数。School 经既有系统 API 新发明确委托，未恢复已撤销旧根。JWT 的近期 proof 是测试 fixture，不声称真人完成 MFA 仪式。
- 页面最后一次 7 个场景通过，覆盖 School/Teacher、未知结果回读、不同意图冲突、学校切换、历史/空接收者等。独立 API 4 与既有系统授权页面 45 个场景通过；旧父页面 3 个场景已有单独原报告。这里不把重叠的页面迭代相加。
- 新独立克隆库跨报告 4 个场景通过：使用既有完整 R 与 `none-v1` 明确无反馈 R，正常系统批准。C/P 与 M 身份相同，R/组合不同；同名跨 R、名称搜索和只提供一个来源页都不能任选；正常撤销重复项后剩余具名配置可选，原两份 T1 不变。该单页 helper 实测两次 SQL，不代表全目录/全平台性能验收。
- 新后端闭包类型检查退出 0；最终前端闭包类型、相关文件 lint 退出 0。前端首轮新测试的 Promise 泛型类型错误原日志保留，修正类型后复验，没有放宽断言或改变生产 tsconfig。

原始报告、命令/退出状态、请求观察与输入 hash 见相邻 verification 与便携原始记录。早先 HTTP/UI 资格与最后 peer 修正分开记录；peer 更改只涉及消费者目录，未重复管理员写入、被试生命周期、素材计分或标准内容检查。全部使用 localhost 的独立合成库及 owner 测试角色，未资格化生产 runtime role。
