## ⚠️ 性能瓶颈分析

### 当前瓶颈 (按影响排序)

1. **带宽瓶颈** (高)
   - 问题: 5M 带宽限制静态资源传输
   - 影响: 图片/视频加载慢
   - 解决: 使用 COS + CDN

2. **数据库连接** (中)
   - 问题: 高并发时连接数增加
   - 影响: 响应时间增加
   - 解决: 连接池优化 + 缓存

3. **bcrypt 计算** (中)
   - 问题: 登录时 CPU 占用高
   - 影响: 登录响应慢
   - 解决: 已是最优，可接受

4. **内存缓存** (低)
   - 问题: 重启后缓存丢失
   - 影响: 首次查询慢
   - 解决: 使用 Redis (可选)

## 📋 性能监控指标

### 关键指标 (KPIs)

| 指标 | 健康阈值 | 警告阈值 | 危险阈值 |
|-----|---------|---------|---------|
| API 响应时间 | <100ms | 100-300ms | >300ms |
| CPU 使用率 | <70% | 70-85% | >85% |
| 内存使用率 | <70% | 70-85% | >85% |
| 数据库连接 | <50 | 50-80 | >80 |
| 错误率 | <0.1% | 0.1-1% | >1% |
| 带宽使用率 | <60% | 60-80% | >80% |

### 监控脚本

```bash
#!/bin/bash
# monitor.sh - 系统监控脚本

# CPU 检查
CPU=$(top -bn1 | grep "Cpu(s)" | awk '{print $2}' | cut -d'%' -f1)
if (( $(echo "$CPU > 80" | bc -l) )); then
  echo "[WARN] CPU usage: ${CPU}%" >> /var/log/ptool/monitor.log
fi

# 内存检查
MEMORY=$(free | grep Mem | awk '{printf "%.2f", $3/$2 * 100}')
if (( $(echo "$MEMORY > 80" | bc -l) )); then
  echo "[WARN] Memory usage: ${MEMORY}%" >> /var/log/ptool/monitor.log
fi

# 数据库连接
CONNECTIONS=$(sudo -u postgres psql -t -c "SELECT count(*) FROM pg_stat_activity;")
if [ "$CONNECTIONS" -gt 80 ]; then
  echo "[WARN] DB connections: $CONNECTIONS" >> /var/log/ptool/monitor.log
fi
```
