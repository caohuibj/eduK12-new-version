# 在对话中使用 EDUK12 量表工作流

这是使用入口，不另维护业务规范。唯一规范与模板在 [eduk12-scale-intake Skill](../../.agents/skills/eduk12-scale-intake/SKILL.md)。版本 1.0.0。

## A. 已加载本仓库 Skill 的 Codex / Work 对话

确认该对话的 checkout 包含此 Skill（尚在文档分支时不能声称 main 已有）。明确调用：

> 使用 $eduk12-scale-intake 处理附件中的量表（或这组 GitHub 文件）。按仓库规范完成来源去重、三个子版本审计修复、报告润色与图表优化、分类附注和最小验证。先读取本次实际授权范围。仅在已明确授权的操作、目标环境、可见性和入口范围内安装、发布并回读；“入库”未明确包含公开发布时，不自动设为 PUBLIC。缺权限或环境信息时先完成可移交包，明确未执行项。一项阻塞不影响其他工具。Notion 逐项记录，回复实际结果与链接。

支持传原始条目或已有成品包；请尽量给出名称/出处（自编注明）、条目、对象/用途，选项若有附上。不要求先有阈值或报告。

## B. 新 GPT 对话没有自动识别 Skill

仓库里有文件不代表每个聊天窗口自动装载。请提供 **SKILL.md 的固定提交 GitHub 链接**，要求读取其引用的工作流和模板；若链接/连接不可访问，把整个 Skill 文件夹打包上传，并要求先读取文件。可以直接复制：

> 请读取我提供的 EDUK12 量表 Skill 及其 references/workflow.md，按它处理这些材料。先说明当前能否读取仓库、写 GitHub、访问 Notion 和指定系统环境。已有连接和授权范围内直接执行；没有连接时只完成审计与入库包，不声称已提交、已写 Notion 或数据库已导入。无需先给我泛泛方案，直接从材料识别和三子版本处理开始。

上传技能文件或发一句指令不能授予账号权限，也不能保证聊天结束后持续运行。需要实际安装/发布时，使用具备对应执行工具和授权身份的云端任务。不要把密码、密钥、会话令牌放进指令、量表包或记录。

## C. 一句话续办

> 使用同一版本的 $eduk12-scale-intake，读取这个批次 manifest 和逐项记录，先核对真实远端/系统状态，只续做未完成或输入改变的步骤。不要重跑已通过且仍有效的检查。

## 指定入库范围的示例

> 本批允许审计、修复、在独立内容分支提交推送，并导入【明确环境】的公共库。使用已有合法操作身份，范围为【实际批准的入口/可见性】。不部署、不改账号授权、不发布实际测评任务。若环境尚未加载该版本，先完成包与提交，报告该阻塞。

方括号由真实目标填入，不猜默认生产环境。既有对话已明确这些信息时无需反复询问。合并/部署及改变访问授权不是技能自动附带的权限。

## 获得什么结果

每工具一份实际系统格式包及三个版本、修改摘要、标签/来源附注和必要证据；每批一个可恢复记录；Notion逐项状态；有系统权限且实际执行时附 scaleId、安装/公开状态和精确版本回读。没有阈值可明确 none；不能确认计分时说明缺项，不捏造规则。

## 当前交付边界

本次提供的是可由 AI 使用的操作规范和记录模板，没有安装新的聊天插件，没有新增后端批处理 API，没有运行任何量表入库。现有命令和当前 School/Teacher 功能接线需按实际版本核实。仅修改这些文档/模板不需要全平台构建或数据库测试。
