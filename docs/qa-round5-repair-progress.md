## PR #243 review 修订

Review 对照的是 `f454a6c9`。第一项在较新的 `0df74389` 已修复；本次保留并重跑真实数据库验证。其余五项意见成立，已按以下方式处理：

1. 结束研究原子停用所属波次 token，拒绝直接匿名新作答；原答卷恢复、历史统计、无关普通链接和其他研究保持可用。
2. 固定包认知 wrapper 同所有者时继承来源 root，同时继承 `maxAttempts`；跨所有者不冒用他人的 root。真实 PostgreSQL 覆盖独立、组合测评、旧综合测评、固定包四入口先后与并发争抢一次额度，以及原会话无额外计次恢复。通用多答卷生命周期 fixture 显式设置 100 次，限额回归仍严格设置 1 次。
3. 保留七天运行时审核有效期，已发布版本增加独立续审入口及到期状态；登记者仍不能自审，每次审批成功清空四项审核确认。时间推进验证到期拒绝新准入、独立续审同一 hash 恢复准入、内容和历史冻结报告不改写。
4. 登记阶段比对代码目录同 key/version 的声明式包 hash；不同内容立即拒绝，完全一致可幂等登记，避免发布后目录刷新才失败。
5. `installedBy` 记录登记者，签名 `reviewerId` 记录独立审核者，`publishedBy` 记录实际调用发布的管理员。独立审核约束以登记者为基准；底层签名接口也不能借另一发布者接受登记者自审。
6. 波次创建响应成功即显示成功并清理请求意图；统计/链接刷新失败另报刷新提示，不误报创建失败。两种刷新失败及原网络重试复用 UUID 均有 UI 回归；结束研究后的链接刷新采用同样的已提交状态提示。

## PR #243 第二轮 review 修订

Review 基于 `b319afd8`。管理员范围和部分报告状态是可复现的实现问题；测评中途反馈是需要明确的产品与施测规则，不把 review 中的影响示例当作本系统已实证的效应。HOLD 的恢复规则此前未形成一致的前后端合同。本次选择并实现以下边界：

1. 管理员课程工作台的认知质量查询沿用管理员跨创建者范围，仍限定当前课程、已登录作答和合法普通产品；教师继续只查询自己的记录。真实 PostgreSQL 验证管理员能看到另一教师的数据，且不混入无关课程。
2. 参与者默认完成整份测评后才能查看允许的单项反馈；教师保留普通组合的部分报告。服务端同时约束旧 `?partial` 链接、认知历史/会话、量表读取、SJT 读取和登录/匿名 FINAL 返回；未完成时仅返回提交确认与延后反馈状态，页面给出明确提示。完成后恢复原冻结结果，独立测评及关系型更严格的受众规则保留。没有新增逐项反馈开关。
3. `partialReportAvailable` 和 `partialReportUnitCount` 按当前 epoch、有效冻结记录及已完成的 SCALE/COGNITIVE/SITUATIONAL FINAL 推导；零结果和仅背景表单不开放部分报告。旧运行时批量查询实际完成单项，避免逐行查询。
4. HOLD 只能经暂停之后的新独立审核恢复 PUBLISHED。审核时间进入签名并限定七天有效期；暂停前的签名和登记者自审均拒绝，RETIRED 不可恢复。后台提供四项重新确认、管理确认和“重新审核并恢复发布”。旧无审核时间的签名仍兼容已发布准入，但不能恢复 HOLD；本轮没有新增数据库迁移。
5. 重复归档成为严格 no-op：当前或原重试 revision 均返回已归档记录，不递增 revision、不重复写审计；仍先验证权限及产品边界。
