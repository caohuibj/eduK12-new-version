这7例在最后一次stimulus回调时均约49.9ms，距名义50ms尚差约0.1ms，源码的elapsed>=50判定因此为false；下一保存回调约16.7ms后到来，elapsed约66.6ms，为true，转入mask。最后0.1ms差距不是仅把‘精确50.0ms减法的二进制尾数’当成49.9ms；已有API时间戳本身落在阈值以下。不能据此把浮点/时钟分辨率或浏览器机制认定为独立根因。

首次stimulus记录与core onset一致；首次mask记录与core maskOnset一致。capture在首次stimulus rAF设置onset、按同一传入timestamp记帧，Task随后在同回调发出canvas绘制命令。由此可核当前记录计数并无一帧的onset标签偏移；尚不能证明这些命令对应的实际屏幕像素onset/offset。

七例保存间隔约16.6–16.7ms，没有overflow/incomplete标记，保存序列没有一个异常长间隔可以解释为丢失回调。没有额外独立测量计时精度、浏览器量化、compositor调度、真实刷新或物理曝光，因此不能把具体浏览器机制/系统负载/设备差异当成已归因结论。

独立审核仍需决定原协议与目标设备的帧量化/容差策略及必要用户确认。这里不提出epsilon，不放宽准入，不静默换成三帧；正式施测继续禁止。完整数值、IEEE754 precision17、25例对照和源码行号见timing-diagnosis.json。
