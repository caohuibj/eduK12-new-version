# 标准认知测试配色合集：项目提案

2026-10-26 用户纠正：中性不是全灰阶，而是不带入口品牌偏好，使用统一、可识别、符合任务协议的标准配色。前一轮“所有内容灰阶化”要求撤回。以下是项目标准候选，不是国际统一认知测验色标，也不是科学有效性认证。

## 三组色的职责

1. 界面色：统一浅底、深色文字、边界、蓝色操作/焦点；四入口一致。无品牌渐变、装饰色、自动昼夜切换。正式计时刺激区不被按钮/通知/入口色干扰。
2. 刺激色：每个协议单独指定。合集仅提供MOT候选；原协议或任务需要其他背景、色相、亮度时按协议冻结，不能为了统一色板静默替换。相同任务的长版/体验版、四入口共享同一已冻结配色。
3. 报告类别色：参考Okabe–Ito/CUD八色，配文字、标记或线型。不是8种能力，也不意味着8色同时用于刺激。黄色/天蓝等浅色不直接用于白底小字号文字或无边界目标。

具体sRGB色号、RGB255、计算相对亮度、用途和限制见colors.json。不会把其字段直接宣称为当前runtime schema；未来按实际呈现/配置快照契约接入。

## 首项多目标追踪

- 区域底色：#F2F2F2；全部运动对象：#222222。
- 1000ms提示阶段：5个目标#E53935，5个其他对象#222222；提示结束后10个对象全部#222222。
- 停止后的已选对象：#1D4ED8，加白色勾号/描边，只表示已选，不提示正确与否。
- 目标红沿用上游的红色提示思路；这里具体色值、背景、程序化圆点是本项目拟定值，不宣称复刻上游RGB。相较上一轮灰阶稿的变更已经显式登记。
- 这些色值的普通sRGB对比度已计算；不是色觉检查或个体识别保证。某些色觉差异可能影响红色识别，需要任务理解/识别验证；若更换色相、加环或改形状，产生独立协议变式并评估可比性，不能偷偷启用“色盲模式”混入同一参照。

## 可读性和测量边界

- 普通文字采用WCAG 2.2对比度目标：常规文字至少4.5:1，必要控件/状态图形至少3:1。阈值只在相应可访问性范围使用；不能拿WCAG通过代替刺激效度，也不能把其要求机械套到刻意控制对比的视觉实验。
- 亮度字段为按sRGB公式算的相对亮度，非仪器测得cd/m²，不标等亮度或知觉均匀。
- 色觉差异、显示器色域/亮度、浏览器色彩管理、自动亮度/护眼/夜间色温等可能影响呈现。按实际可获得能力记录/说明，不声称网页能可靠读取或锁定系统设置。
- 若研究要求物理亮度、等亮度、色觉分离等，需要校准设备和对应协议，不能由HEX色号替代。
- 所有刺激颜色、背景、透明度、描边、反馈阶段进入实际协议与呈现快照；变更按测量语义评估版本和参照，旧冻结结果不覆盖。
- 相同源码RGB只保证指定值一致，不能证明跨设备真实光谱/亮度相同；常模汇总仍按实际协议、profile、输入、语言、校准和人群核对。

## 来源与当前证据

- [W3C文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。
- [Okabe–Ito / Color Universal Design](https://jfly.uni-koeln.de/color/)：报告类别色与冗余标记参考；本项目色板不是全人群保证。
- [PsychoPy颜色空间说明](https://psychopy.org/general/colours.html)：颜色空间与校准。

本轮只制作设计资料和静态浏览器截图，不改运行时、计分、输入或数据库，不触发CI、push、合并、部署。目标为角色映射、sRGB对比度、可见阶段/状态及静态布局核对；真实设备、色觉、四入口运行链和科学效度未验证。预算约5分钟反馈实际阶段，不扩大成全量测试。
