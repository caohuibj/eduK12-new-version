# 从 GitHub 来源到具体认知任务协议

> 研究快照；仅静态源码审阅。**来源卡不是后台可直接导入的配置，也不是入库、运行验收、科学有效性或上线结论。**

本轮接续[第一轮 34 个仓库来源评审](../source-survey-20261026/README.md)，把优先来源拆成可追溯的单任务协议卡。先选清楚刺激、反应规则、阶段、原始字段、计分、质量限制和报告措辞，再决定是否值得实现；不因有源码就上线。

## 决策摘要

**整理了 13 张单任务协议卡，选择 6 项优先继续完成协议定稿，7 项保留研究储备。** 另补查 5 个来源项目家族：新增优先主库为 Tatool；cognitive-battery、ResearchKit 作为专题参考；TaskBeacon 仅作发现索引，ResearchStack 不计认知内容来源。补查不是再添 5 个已可用工具。

优先级综合考虑领域增益、协议可追溯性、素材与许可、数据和解释负担；不是按星数排序，也不是上线顺序。“优先定稿”仍有下表所列决定未完成，不能改写为已可导入或已经完成验证。

| 优先继续定稿 | 为什么先做 | 必须先明确的最小问题 | 拟用策略 |
|---|---|---|---|
| [注意网络 PANT](attention-task-cards.md#attention-ant-pebl) | 给已有侧翼干扰任务补线索条件，原文与源码可比 | 中性无侧翼变式、固定输入设备、正确试次口径；块摘要须从原始记录重算 | 文献自研 |
| [多目标追踪](attention-task-cards.md#attention-mot-flower) | 补动态视觉追踪，并按速度给直观正确目标数 | 5 个目标/10 个对象、实际刷新率与轨迹；自制素材，不能照搬有静态风险的运行器 | 文献自研 |
| [短时点数判断](attention-task-cards.md#attention-enumeration-flower) | 补短暂数量报告，不把它冒充数学能力 | 论文 5°与代码 7°区域二选一；50 ms 呈现、掩蔽和滑杆语义 | 文献自研 |
| [连续图像再认](memory-decision-task-cards.md#continuous-recognition) | 补连续新旧判断及误认控制，序列结构明确 | 图片获权、间隔归属；原评分面向图片，个人会话汇总须另定义 | 代码适配，素材另审 |
| [空间位置精度工作记忆](memory-decision-task-cards.md#precision-working-memory) | 补连续误差测量，区别于记忆广度 | 1/5 个位置、400 正式试次与约 25–30 分钟负担；视角校准、模型可靠性 | 文献自研 |

## 领域覆盖与主干去重矩阵

对照仅基于固定历史主干，详见 [24 家族基线](baseline-family-map.json)。下列“新增家族候选”只是研究归类；不能把 24+11 写成当前已有 35 项，也不能按 13 张卡宣布新增 13 范式。最终归类仍须按六个协议轴复核。

|---|---|---|---|
| [PANT 注意网络](attention-task-cards.md#attention-ant-pebl) / 线索与干扰 | `flanker` | 协议变体候选：同含侧翼干扰，另有四类提示与网络差值 | 优先定稿 |

| [注意闪瞬](attention-task-cards.md#attention-blink-holcombe) / 时间选择 | `cpt` | 新增家族候选：快速字母流中双目标及间隔，区别于持续目标检测 | 储备，先真实呈现和条件分母 |

| [连续再认](memory-decision-task-cards.md#continuous-recognition) / 学习记忆 | `wordlist`、`pairedassociate`、`picturesequence` | 新增家族候选：连续流新旧判断及重复间隔；不同于回忆、联结或顺序再现 | 优先定稿 |
| [位置精度工作记忆](memory-decision-task-cards.md#precision-working-memory) / 连续空间误差 | `memory`、`corsi`、`nback` | 新增家族候选：颜色提示圆周位置再现；不是数字/空间广度或朝向报告 | 优先定稿 |
| [Horizon](memory-decision-task-cards.md#horizon-exploration) / 探索选择 | `reversallearning`、`bart` | 新增家族候选：强制采样后比较剩余选择机会，不以奖励总数代表探索能力 | 储备，3 局 demo 不作完整协议 |
| [两阶段学习](memory-decision-task-cards.md#two-stage-learning) / 转移与奖励学习 | `reversallearning` | 新增家族候选：两阶段状态转移和奖励轨迹，模型分析另审 | 储备，先日志与分析契约 |
| [气球努力](memory-decision-task-cards.md#balloon-effort) / 努力与收益 | `bart` | 新增家族候选：选择按压成本及比例奖励，不是爆破风险 | 有条件优先定稿 |

13 卡按上表为 2 项协议变体候选、11 项新增家族候选；这些是研究去重标签，**不是正式新增入库数**。7 项注意/执行卡来自 4 个主来源仓，6 项记忆/决策卡来自 6 个主来源仓，共 10 个主来源仓。OpenSesame 仅为注意闪瞬交叉变式，不增加第 14 张卡；素材许可证据仓也不算任务主来源。补查的 Tatool Mapping、Sternberg 和移动 Stroop 是来源抽样，不冒充本轮新增独立协议卡。

[补查报告](additional-sources.md) 独立记录 **5 项目家族、5 主评审仓＋4 配套证据仓**。其中 TaskBeacon 的 138 项是来源索引自报条目经静态数数核对，不是审查通过数；本轮只深入 MID 一对。第一轮的 34 仓保留原口径，不与家族数或配套仓数直接相加。

## 读卡时必须分开的判断

### 版权去向与实现策略

版权按拟采用材料逐项记录为 **可 GitHub 公开／获权后系统用但不公开／待联系授权**。条件许可、代码与刺激素材可有不同结论；“可 GitHub 公开”不是无条件可商用，也不是整仓所有素材均获权。未获许可时，不以“只在系统中使用”代替授权。

实现策略另列 **代码适配／文献自研／暂缓**。授权不明不妨碍研究可靠文献、独立确定方案，但不得据此复制代码、刺激、题库、译文或商标。非商业、署名、同方式共享、许可证兼容和素材条款须各自满足。

### 参数不是都叫阈值

试次数、刺激时间、反应截止、条件比例、难度阶梯是协议参数；只有明确承担质量判断或参照解释的规则才归入阈值。固定使用四类：

| 类型 | 用途与边界 |
|---|---|
| 技术质量规则 | 记录完整性、计时、中断、试次数等；不据此把人分成能力高低。 |
| 理论参照 | 在明确假设下的机会正确率等；不是同龄常模。 |
| 文献经验 | 原研究的样本、协议、设备和经验规则；不能直接变成中国儿童标准。 |
| 项目暂定研究者规则 | 没有充分外部证据时透明提出的研究规则；需理由、负责人、版本、复核条件，不作能力等级。 |

未找到适用阈值可以保持未定；不能用漂亮的数字补空白。技术通过、研究试行和科学解释资格分别判断。

### 给普通用户的报告

先说本次做了什么、记录是否足够、哪些指标能解释，再用次数、比例、毫秒和分母描述本次表现。专业模型和公式留在研究层。**缺失值不填 0；有符号差值、斜率和 d′ 等负值不裁零；没有真实适用常模就不生成同龄百分位。** 不把奖励数、平均信心、教学分数或为了兼容接口而填的数冒充能力总分。

每张协议卡给出可解释、受限、无效三种报告样例。样例不是现成发布反馈；还须绑定实际指标和质量规则。对“更分散”“更常选择”“答对时更有把握”等方向性描述，只有真实记录支持时才使用；反向按实际写，不能支持差异时只列条件记录，不宣称等效。普通首屏将 HR/FAR 等换成中文次数、比例和分母。无效时不向用户输出表现结论，保留的内部数据不等于可展示结果。

## 平台接入边界

[baseline-admission-map.md](baseline-admission-map.md) 说明固定基线的注册、计分、版本冻结、导出、报告隐藏和 Survey 限制；[candidate-qc-template.json](candidate-qc-template.json) 是研究登记模板，**不是实际导入格式**。

固定基线中的 Survey 只有指定 Go/No-Go 协议入口。候选需要的其他流程、参数、指标或无总体分注册能力，先列精确依赖，再由 PR #356 对应平台负责人按其**实际固定 head**复核是否已满足。本轮不判断当前 #356 仍缺什么、已完成什么或已发布什么，也不在内容分支补平台能力。

## 审阅方法与停止边界

各来源以完整 GitHub commit SHA、具体任务/计分/许可证路径为依据；实际读到什么就报告什么，文件存在不等于行为验证，未找到不等于不存在。代码许可、刺激许可、原始范式论文、实现效度和本地常模是不同证据。

本轮只做研究文档、结构化数据一致性和引用核对；没有运行第三方任务、安装依赖、启动服务/数据库、测试计时、做受试实验、运行应用验收或 CI，也没有修改代码、注册表、公开库、数据库或发布状态。未来需要的 golden、empty、insufficient、异常事件、负值/null、冻结重放、报告和导出检查只是计划，不记作已通过。
