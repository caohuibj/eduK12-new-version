## 撤权语义

grant/revoke 与 tokenVersion 在一个事务中提交，无权限 TTL 缓存。提交后开始的下一次认证数据库读取即看到新版本，旧会话返回 401；重新登录后已撤销入口返回 403。浏览器样本从发起撤权 POST 到随后拒绝 GET 共 `35.85 ms`，包含两个 HTTP 请求及提交开销，不能当作精确 commit→deny 延迟或生产 SLA。

已经完成认证的在途普通业务请求可以完成；本实现不声称撤回已发送的数据或取消所有在途 SQL。关键授权、研究者/教育授权事务通过用户/授权行锁与撤权排序；导出在最终发布事务中持有用户共享锁并核对版本，撤权后不能发布旧任务。重新授权会产生新版本，不能复用旧版本任务。需要更强的全业务在途取消语义时应另行设计，不能通过长时间全局持锁假称即时撤销。

## A06 迁移、恢复和效率

两份新 migration 以事务重放，授权状态 SHA-256 保持一致。真实 PostgreSQL dump→新数据库恢复后 SHA-256 相同；受限运行身份验证 219 表、1 个序列及 177 份精确迁移。审计修改、TRUNCATE、禁用触发器 3 项拒绝；新表共 9 个索引。该次合成夹具快照为 22 grants、66 audits、20 keys，新表含索引共 `245760 bytes`。原始 dump 留在私有目录，不上传。

小规模单进程测量：30 次 principal 读取均为 1 SQL，P50 `0.390 ms`、P95 `0.716 ms`；25 人和 8 人列表各 10 次均为 3 SQL，无 N+1。列表 P50 分别 `5.103/3.819 ms`，P95 `36.169/8.401 ms`，包含首个 HTTP 连接样本。该段进程 CPU user/system 为 `162.6/15.4 ms`，RSS `162.5→165.9 MiB`。这是开发样本，不是并发容量、长期内存稳定性或性能改善证明。

历史 `20260919000100_platform_role` SQL 不改校验值，也不无差别降权。升级起点若早于该迁移，必须先人工盘点其 ADMIN→SYSTEM_ADMIN 一次性映射；没有受控登记及安全密钥，不取得可用管理会话。真实账号复核、创建、票据、密钥和配置由用户另行授权，本轮未执行。

回退保留增量表、已撤销 grant、版本和审计，不能恢复旧数据库。缺少本次授权/强认证边界的旧二进制不受支持。`admin-permissions-rollback-preflight.mjs <精确SHA>` 只读比较当前安全输入与候选，拒绝改变安全下限的回退，不部署任何内容。实际旧版回退必须采用保留这些安全输入的兼容修复代码与合格产物。
