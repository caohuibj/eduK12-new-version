# Education feedback integration seam

Branch: `feat/pr363-education-feedback`, starts at `6cf241d65b4bc44878ef9d9fe21c81fdd02561cd`. This is the feedback task line; source registry/authority/migrations and new Teacher runtime remain with root/other worker.

## Frontend

`EducationTaskFeedback` props: `entry: SCHOOL|TEACHER`, `executionId`, `title`, product-bound `api`, stable `loadFeedback(): Promise<EducationFeedbackData>`, `onClose`, optional `renderLegacy(data)`. Key it to execution and identity scope. Mount only after authoritative parent `COMPLETED`, or a separate real accepted whole-submit ACK host; a child receipt is not whole completion. It always preserves accepted completion, reads once, exposes explicit refresh/retry/close, and discards late replies after identity/task switch or close. It does not poll, submit, or cache cross-request authorization.

Existing School/Teacher Scale consumers retain their product-owned report paths. School's optional runner `onParentCompleted()` is emitted only from an actual loaded parent COMPLETED, never from a child FINAL response, and excluded for observers. Other Teacher multi-tool hosts can use the shared component with `/assessment-reports/executions/:executionId` and their own stable loader.

DTO recognizes `EDUCATION_SCALE_PERSONAL_REPORT` and new `EDUCATION_ASSESSMENT_PERSONAL_REPORT`, schemaVersion 1. The new DTO has `state: READY|WITHHELD|COMPLETED|PENDING`, `mode`, `message`, optional `releaseAt`, and `reports: [{itemId,family,status,rendered,message?}]` for READY. Each rendered object is existing `renderDeclaredReport` output. Missing/withdrawn/unavailable templates are explicit statuses; there is no raw metrics fallback. ASSET nodes show alt text only; this does not create an unprotected resource URL.

## Backend wiring required from root

Production is now composed in `education-assessment-report.service.ts` and mounted in backend index. The reusable `createEducationAssessmentReportReader(deps)` requires both (the factory is generic, retaining root's wider source/authority/runtime types):

1. `readSource(tx,{product,organizationId,resourceKey,resourceVersion,purpose:'HISTORY',executionId,compositeId})` returning `null` or `{identityOnly:true,origin,entry,runtime:{id},releases:ReadonlyMap<string,StoredRelease>,authority:ReadonlyArray<unknown>}`. Structurally wider root runtime/source objects are compatible. `origin` is existing `EducationAssessmentOrigin`; key is `education-assessment:PRODUCT:ORGANIZATION_UUID:RESOURCE_UUID`, version `1.0.0`.
2. `assertSourceAuthority(tx,{actorUserId,executionId,product,organizationId,source,purpose:'REPORT_READ'}): Promise<void>` which binds the verified source to the exact product/organization and historical source scope. Production first uses the root FROZEN fence; current caller report rights are independently enforced by the reader's actual REPORT_READ owner/member/population SQL and final recheck. `identityOnly` is never this caller grant. No permissive default adapter, process registration, or authorization cache exists.

The actual root reader is `readEducationAssessmentDeliveryIdentity(tx,{resourceKey,version,purpose})`; adapt `resourceVersion` to `version`. Its `authority` proof array is required and compared unchanged after asynchronous reads; the complete source/runtime types survive generic type inference. As of normally absorbed root `0e3d210d`, `origin.runtimeDefinitionHash` and `origin.distribution:{actorId,grants:[{resourceId,grantId,version}]}` are required identity fields. The complete origin, including these original proofs, is rechecked unchanged. FROZEN history does not reapply current distribution/issuer admission; caller REPORT_READ revocation and emergency stops remain enforced. No source module is edited beyond the normally absorbed root commits.

The production composition reuses `assertEducationAssessmentExecutionSource(tx,{executionId,compositeId,purpose:'FROZEN'})`; it does not apply current new-use or issuer qualification to report history. It mounts `createEducationAssessmentReportRouter('SCHOOL', reader)` at `/api/campus`, and the TEACHER router at `/api/huiteacher`. Both enforce the corresponding authentication middleware; School also checks student approval. There is no Training cookie/session-ID transport. School's task DTO supplies `feedbackNamespace:'EDUCATION_ASSESSMENT'` for the exact new namespace, and the frontend calls the dedicated endpoint. Old tasks keep their old path without an additional probe.

The reader checks current product membership, self respondent/subject, report denies, current population, resource key/version/policy, parent/assignment identity, real async job identity, and rechecks current source/authority after async materialization. A READY report additionally consumes `readRespondentRunSummary(user,execution,{disclosureOnly:true})` as an independent current disclosure ceiling. The new internal overload returns authorized metric keys without flattening unit facts; the report reader separately verifies canonical facts per unit. Original two-argument consumers and ambiguity refusal are retained. Identically named metrics in different approved units remain separate reports.

## Shared FINAL input needed

The actual education runtime must have the existing frozen `trainingContentBinding` + hash, optional `trainingReferenceBinding` + hash, encrypted `trainingContentInterpretation` + hash, aggregate input hash, active slots and current-epoch canonical UNIT_RESULT rows. The shared interpreter must have produced that receipt at FINAL/worker time. The reader decodes it and renders existing facts; it does not invoke scorers, reference selection or new interpretation on GET. Origin unit item IDs and C/P/R pointers must equal those bindings. A source-validated pure Form BUNDLE with empty measurement units is the deliberate exception: actual parent COMPLETED produces completion confirmation without measurement/interpretation rows or numeric feedback. Missing verifiable receipt is WITHHELD, not synthetic PENDING. Real PENDING requires an actual matching PENDING/PROCESSING job and accepted submission/current completion.

Report content audience must exactly be `student` for SCHOOL or `teacher` for TEACHER, with exact frozen source identity and current caller report authority. A PRIVATE report from another product, including TRAINING, is refused. A shared/platform report still needs the explicit source authority callback. No template is created, approved or auto-published by this task line.

Release-time behavior reuses `evaluateTrainingFeedbackForAttempt`; root must preserve any applicable frozen feedback policy when constructing the education delivery. For an education opening contract, inject optional `readReportOpening(tx,{actorUserId,executionId,product,organizationId,source,attemptId,attemptEpoch}) -> {releaseAt:string|null}` from the actual frozen configuration. The service enforces a future opening, rejects invalid dates, and rechecks that opening after asynchronous materialization. Null means no extra opening restriction; it cannot widen a configured shared frozen policy. No new timestamp is inferred or persisted by this reader. Report images are intentionally not served by this new DTO; authorized ASSET delivery remains a separately scoped integration item.
