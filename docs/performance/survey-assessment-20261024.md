## 修改与边界

- 研究者的发布、私有报告、数据面板首次访问才挂载；已访问编辑器保持挂载，
  保留未保存内容、离开风险检查和深链接。更换项目时不沿用旧项目的访问记录。
- 纯文字量表跳过媒体状态/effect 与播放器代码；有图片或视频时按需加载原有
  实现，继续使用原授权凭证、图片就绪与完整观看门禁，加载失败可主动重试。
- 被试流程结果只在任务/答案变化时计算；量表视图及表单题目索引复用稳定输入，
  不因题页、计时、提示或忙碌状态重新构造整套定义。计时和 FINAL 协议不变。
- 公共量表任务响应共享相同的响应选项。逐题选项的 key、label、顺序或长度
  只要不同就保留覆盖；冻结定义、计分、维度及授权均不改变。
- 导出增加可选 `?part=csv|codebook|manifest`，网页只下载当前文件。旧客户端
  仍能读取原完整响应。每次请求仍执行既有 MFA、当前项目所有权/修订、有效期、
  解密、完整摘要校验与审计；没有添加答案/权限缓存，也不削弱撤权检查。

## 小样本实测

独立 loopback 云端预览、PostgreSQL 测试库，真实 API 创建/显式发布/开放合成
研究。60 题逐题量表 + 两页表单，前后各两个独立浏览器上下文；研究者各一个。
Chromium、TLS 固定临时证书、100ms 网络延迟、500KB/s 下载、250KB/s 上传、4 倍
CPU 限速。表内被试耗时取两个样本中位数；研究者仅单样本。完整数字见同名 JSON。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|

| 被试首屏 JS 实际传输 | 97,057B | 89,786B |
| 开始本轮至第一题可答 | 417ms | 345ms |
| 量表/表单 task 响应解码体积 | 20,293B | 5,893B |

三个导出文件各自的 SHA-256 前后一致；候选浏览器又经真实 API 发起三次下载，
验证 CSV 的 UTF-8 BOM、CSV 内容和 JSON 解析，以及网页下载发起状态。
刷新恢复检查确认量表选项、两页表单答案保留，并能正式提交成功；没有页面异常。

延迟挂载会把工作移到实际访问的标签：首次发布面板约 204→1,450ms，报告
109→300ms，数据188→281ms。旧页面已在设置阶段提前完成了这些读取；不能将
初始页面节省的工作再次算作这些面板的速度收益。

## 资源与验证限制

研究者设置页 renderer TaskDuration 约 1.02→0.77s，JS heap 5.72→3.87MiB；
只是单次浏览器观察。逐题量表 CPU、heap 和提交延迟没有稳定的普遍改善证据。
Docker CPU 累积值、working set、Chromium 进程 CPU/RSS 每 500ms 留存。被试
逐题两侧均无 HTTP，未增加逐题数据库调用；没有把 API 数量当作 SQL 数量。

候选开发后端采样约 616MB，包含文件监听重启/编译预热；稍后空闲 Docker
working set 回落至约 298.9MiB，旧采样约291MB。该过程不能证明内存改善或
稳定回退。Chrome RSS 是进程求和，包含共享页，也不等同于独占内存。
未做并发/容量压测，不推断最大人数或生产服务器资源节省比例。

两次测量脚本定位失败（题干星号、自换题 radio 的 check 定位）分别保留原记录，
修复定位后才完成上述对照，不把失败记录算作通过。认知固定120试次及 SJT
没有新增整场浏览器实测，不修改科学参数以缩短测试；受影响公共入口的既有
组件合同检查负责这些分支的集成验证。

主要检查位置：本地执行实际构建和合成浏览器观察；Actions 执行当前前端
类型/变化文件 lint、列明的 Survey 消费者测试、后端编译与受影响合同、新的
范围/拒绝合同和 SAST，复用仍有效且输入未变的官方依赖审计。没有全量回归、
数据库迁移/恢复、媒体 worker、生产镜像或生产部署。本地记录是经审阅的未签名
观察，不冒充 Actions 执行。精确候选以本轮 binding 及真实 ready gate 为准。

原始观察、失败历史、硬件采样、截图和构建位于独立节点
