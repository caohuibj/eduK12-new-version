# Training 教师编制与导出：第二轮优化

本轮接续学员／教师访问优化，集中检查教师登录、工具页、量表／表单新建与保存、报告导出。
基线是已推送的 `16ba12f1799bcaa050c08e807194cfb6426e6df5`；对应应用产物来自
`bba2ce477ad73b7ea14ce62dae563e92aa84e370`（其后只改文档）。main 在开始时核验为
`3c8b0ad97f664b10fb0abcb5884606c18f9ac4be`，本轮不反复更新基线。
工作分支为 `work/participant-access-20261023`。没有修改后端、数据库、权限、科学计分与发布协议。

## 评估与修订

上一轮已显著缩减登录入口，因此本轮登录没有发现需要再次修改的明确问题。
教师编制页面还有中等规模的减量空间：工具页提前引入媒体上传与参考管理，
量表新建页提前引入定义编辑器和素材适配层，表单新建页提前引入组合测评的报告与投放工具。

- `TrainingLibrary` 按用户展开管理区或上传操作加载相应代码。
- `ScaleEdit` 先呈现基本信息；首次进入响应选项、题目、计分或报告区时加载共享定义编辑器。
  `ScaleEditDefinition` 只组合既有共享编辑器与 Training 素材适配器。
  首次打开后继续保留挂载，批量题干／选项在切回基本信息后不会丢失，未应用内容的离开和写入保护继续有效。
- `QuestionnaireProducts` 的报告工作台、参考选择、投放管理、工具／整份表单选择和高级表单导出各自按渲染需求加载。
  独立表单不下载这些不适用的模块；局部 Suspense 保留页面主体及其编辑状态。
- 高级表单导出用同步 in-flight 标识防止快速点击重复提交，失败后允许重试。
- `waitForExportArtifacts` 在一次等待内记住已 READY 的文件，等待其他文件时只轮询未完成文件。
  缓存不跨任务／账号／等待调用，实际下载继续走原鉴权及到期校验。确定性的双文件、三轮夹具需要 4 次状态请求；原逐轮全查逻辑需要 6 次。

没有为尚不明确的数据库或大规模导出改写执行路径。组合导出涉及冻结作答投影、授权与资源上限，
本轮只读检查确认这些边界仍在，未以移除校验换取速度。

## 实测结果

每种版本顺序执行两轮，使用真实合成教师登录及独立测试数据库。
前端使用构建后产物，gzip-6；Chromium 151，4 Mbps 下载、2 Mbps 上传、100 ms 延迟、4 倍 CPU 限速。
各冷页面采用新的已认证浏览器上下文。下表是中位数，KB 为十进制压缩 JS 传输量，含 HTTP 响应头。

| 操作 | 时间：之前 → 之后 | JS：之前 → 之后 | 判断 |
| --- | --- | --- | --- |
| 教师冷登录页 | 1.40 → 1.45 秒 | 159.0 → 158.9 KB | 本轮无明确加速 |
| 工具页冷打开 | 1.94 → 1.96 秒 | 185.6 → 170.4 KB | 减少 8.2%，时间无明确改善 |
| 新建量表冷打开 | 1.93 → 1.96 秒 | 202.9 → 185.3 KB | 减少 8.7%，时间无明确改善 |
| 新建表单冷打开 | 2.68 → 2.45 秒 | 276.6 → 241.8 KB | 减少 12.6%，本样本打开时间减少 8.6% |
| 量表题目首次打开 | 0.083 → 0.325 秒 | 0 → 20.5 KB | 按需加载的代价；后续保留编辑状态 |
| 量表定义保存反馈 | 0.380 → 0.363 秒 | 无新增 JS | API 数量仍为 2，不宣称稳定提速 |
| 表单草稿创建反馈 | 0.350 → 0.354 秒 | 无新增 JS | API 数量仍为 2 |
| 表单题目保存反馈 | 0.256 → 0.276 秒 | 无新增 JS | API 数量仍为 1，无加速证据 |
| 独立报告 JSON 下载 | 0.300 → 0.289 秒 | 无新增 JS | API 数量仍为 1，无稳定加速结论 |

工具页和量表页减量主要节约下载，并不保证当前网络配置下更快。
本轮不把负载转移到首次打开的收益算成所有操作都加速。

每 500 ms 读取服务 cgroup CPU／内存，并记录浏览器进程 RSS。
以表单冷打开为例，API 峰值工作集之前约 298–309 MiB、之后约 311 MiB；
Postgres 约 76–83 → 78–86 MiB；Redis 约 4.3 → 3.7–5.3 MiB；
浏览器 RSS 总和约 856–857 → 851–853 MiB（会重复计算共享页）。
API CPU 窗口消耗之前约 0.031–0.142、之后约 0.075–0.139 核秒。
这些窗口包含 UI 就绪后 700 ms 的稳定观察且长度不同，没有稳定的服务器资源下降证据。
这是单用户小样本，不推断生产并发容量、p95／p99 或每秒可服务人数。

## 已验证与边界

- 前后各两轮真实浏览器流程全部完成：登录、工具冷页、创建量表草稿、批量添加两题（含反向计分）、
  添加总分并纳入题目、保存、刷新确认；创建独立表单、添加反馈题、保存、刷新确认。
- 切换量表分区保留未应用批量题干。相关组件断言同时验证未应用内容时禁止写入与离开确认。
- 四次 JSON 下载均含 7 条原合成作答，文件均为 26,180 字节，内容 SHA-256 全部一致：
  `cf8c2a07ccce408df96cb1f2597ab2e0c8fde07edab4762d42013d8486410da5`。
- 选中 9 个文件、136 项组件／协议检查。首轮 131 通过、5 失败，原因是原测试同步查找懒加载控件；
  改为等待同一控件出现，保留原断言，仅复验这 5 项，全部通过（另 13 项过滤，未重复相加）。
- app TypeScript、全部变化文件 ESLint、唯一一次新前端构建通过，构建耗时 16.71 秒。
  正常保留已有的大 chunk 提示，不通过放宽阈值隐藏提示。
- 探索失败记录保留：第一次合成草稿缺少必需计分项，被服务端拒绝；第二次脚本使用了错误的总分按钮名称。
  修订夹具后才进入上述两轮对比，不将探索失败包装成成功。
- 沿用上一轮已验证的作业／打卡 XLSX 路径；未重复运行不受影响的后端检查、迁移或全量回归。
  高级表单 CSV／ZIP 的去重、轮询、鉴权错误与到期恢复由组件／协议测试覆盖，
  本轮没有开启重型后台消费者，**没有验证 CSV／ZIP 后台生成全流程或大数据量耗时**。
- 本地服务就绪与隔离方式沿用上一轮。正式仓库 ACL 清单遗漏两张 Survey 表的问题未在本性能改动中解决；
  云节点仍使用已记录的本地隔离开发清单，不宣称正式权限验证通过。
- 仅云端内部可访问：开发入口 `http://training.localhost:5173/login`，教师工具 `/toolkit`、
  量表新建 `/scales/new`、表单新建 `/toolkit/forms/new`。这些 localhost 属于云节点，不能由用户 Mac 直接访问。
  新构建测量服务也仅绑定云节点回环端口 5981，无工具提供的公网预览 URL。
