## 评估与修订

| 路径 | 已确认的浪费 | 本轮处理 |
| --- | --- | --- |
| 教师和学员登录 | 入口静态依赖组织管理、报表及其他身份登录页 | 按实际路由加载这些模块 |
| 学员课程 | 查看一个任务标签时同时读取练习和打卡列表 | 首次访问当前标签才读取；当前课程挂载期间复用同一请求；换课或重试重新读取 |
| 学员文字任务 | 无附件也下载 PDF 和视频相关代码 | 有附件时加载媒体组件；打开文档时加载 PDF 阅读器 |
| 会话检查 | 同一身份下并发 focus/visibility 事件可能重复校验 | 只共享进行中的同身份校验；完成后及身份变化仍重新验证 |
| 教师课程和列表 | 未打开的测评、课程设置、素材和匿名链接工具提前加载 | 按标签或首次打开加载；素材选择器首次加载后保留原有状态 |
| 教师作业标签 | 先查全部课程 ID，再查标签 | 用现有创建者关系条件直接查询，保留校园内容排除与角色检查 |
| 教师导出 | 同一按钮连点重复生成 XLSX；读取不参与导出的字段 | 同一任务的进行中请求去重并显示忙碌状态；精确选择导出字段；打卡先验证权限再取提交内容 |

导出仍支持不同任务分别操作、完成后再次导出、失败后重试和页面跳转后完成已请求的下载。现有文件命名、列、单元格保护、权限、保存和幂等协议保留。没有用取消交卷持久化或减少权威读取来换取表面上的提交速度。

此前已完成的 Survey 入口和表单页面按需加载修订保留；用户将重心转向 Training 后，没有扩展 Survey 功能或测试矩阵。

## 查询与导出专项

仅检查当前合成课程。实际浏览器输入三个连续搜索值时均为 **0 次查询请求**；点击“查询”后均为 **1 次**，准确返回一条匹配记录。列表保留摘要字段、分页、权限及筛选条件，没有引入可能失效的跨身份数据缓存。

同一教师对同一练习或打卡按钮在同一事件轮次内连点两次：

| 实际行为 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 练习导出 HTTP / 文件下载数 | 2 / 2 | 1 / 1 |
| 打卡导出 HTTP / 文件下载数 | 2 / 2 | 1 / 1 |

每个列表查询、标签查询及 XLSX 导出端点各做 5 次串行 HTTP 读取。经过本地开发代理，筛选约 311–315 ms，练习导出约 322 ms，打卡导出约 317 ms；前后接近，没有稳定的单次耗时收益。两种导出均为 7 条合成提交加表头，前后工作表 XML 和共享字符串内容 SHA-256 完全相同；压缩包字节受生成元数据影响，未把文件字节变化当成收益。

标签查询省掉一次课程 ID 查询由查询契约用例确认；真实空标签结果在本轮数据上保持一致，非空合成标签由定向用例覆盖。实际 XLSX 内容校验、其他教师拒绝访问、失败重试、重复点击及已请求下载跨页面完成均有对应检查。

大规模直接 XLSX 导出仍会在进程中组织全量导出行和工作簿。大数据量时改为游标分批、流式文件或后台任务可能有收益，但本轮 7 行数据不能证明规模阈值，因此没有仓促改变导出协议、增加队列或启动重型消费者。组合问卷的既有后台导出未做运行验收。

## 资源与适用范围

节点可见 5 个逻辑 CPU，cgroup 配额为 4 CPU / 16 GiB。以 500 ms 间隔读取 API、PostgreSQL、Redis 的容器 CPU 累计值和工作集，并记录 Chromium 进程 RSS 与页面 JS 堆。统计窗口包含可用后 700 ms 的收尾。

教师打卡列表阶段，API 工作集峰值约 309.5 → 318.3 MiB，PostgreSQL 91.7 → 86.3 MiB，Redis 4.3 → 5.5 MiB；浏览器 RSS 求和约 912.7 → 950.8 MiB（共享页重复计入），JS 堆中位数 13.6 → 12.3 MiB。API 该阶段累计 CPU 估计约 0.110 → 0.094 核秒，但阶段长度不同且只有两个样本。**没有证明整体 CPU 或内存稳定下降；当前明确收益主要来自传输和关键路径减少。**

没有进行生产、大并发、生产级表规模、长时间压力或移动设备硬件测试。模拟网络和同机浏览器不能代表用户公网、生产 TLS、CDN、服务器容量或认知测验计时精度。
