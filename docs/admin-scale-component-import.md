# 系统管理员量表组分批量导入

本期提供最小可用的系统管理员入口，完成 Excel 导入 → 可编辑草稿 → 精确组合预览 → 既有批准与试运行 → 上线。管理员页面视觉和进一步交互优化另列后续 PR。

## 范围和身份

- 仅 `SYSTEM_ADMIN` 能下载模板、预览导入、管理草稿和发布；路由和服务端事务均复用现有系统管理员检查。发布继续要求现有管理员二次验证。
- C 为题本、声明式计分和施测元数据；P 为参数、阈值和常模；R 为解释及声明式报告结构。可以提供任意非空组分集合。
- 仅使用既有 `ScaleDefinitionV2`、已安装的 custom scorer、reference 和报告引擎。不上传或执行 JS/TS、Excel 公式，不包含表单、SJT 或认知引擎接入。
- 发布入口范围与个人使用权分开：系统管理员批准具体组合可进入哪些业务入口，原入口管理员/委托服务仍按既有规则签发精确使用权。本功能不改变系统管理员与入口管理身份的边界。

## Excel v1

从“工具库治理 → 批量导入与草稿”下载的 `.xlsx` 含一个完全合成的可导入样例，无真实量表或答卷。

| 工作表 | 普通填写内容 | 高级替代列 |
| --- | --- | --- |
| 基本信息 | `toolKey, configurationName, baseCombinationId, baseCombinationHash, contentVersion, parametersVersion, reportVersion, parametersMode, reportMode`；名称、来源标题/引用/网址/年份、授权状态/再分发/说明、指导语/语言/版本/来源、作答者类型、适用作答者/月龄/年级、题目随机、披露受众/能力、计分版本/缺失策略/最少作答数 | `definitionJson, metadataJson` |
| 题目 | `toolKey`；题号、题干、顺序、选项组、题型、必答、选项随机、用途、注意检测目标 | `itemJson` |
| 选项 | `toolKey`；选项组、选项值、选项文字、分值 | `responseSetJson` |
| 计分 | `toolKey`；指标、类型、名称、方向、主要指标、小数位、来源、题号或指标、权重、聚合、反向 | `scoringJson` |
| 参数 | `toolKey`；参考版本、指标、内容版本、计分版本、参考类型、分档标识/名称、下限含/上限含、参考人群、引用、证据级别、来源类型 | `parametersJson` |
| 报告 | `toolKey`；指标、标题、解释、解释来源、参考版本/类型、分档标识/名称/解释、建议/类别、局限、免责声明、主要指标 | `reportJson` |
| 结构片段 | 高级长 JSON 使用 `toolKey, jsonKey, part, text` | — |

`基本信息` 每个 `toolKey` 一行，每批最多 10 份，文件最大 2 MiB；归档声明展开大小最多 32 MiB、最多 20,000 非空行。列承载完整现有结构，不截断高级字段。

下载默认展示无需 JSON 的完整合成 Likert 样例；高级 JSON 列和“结构片段”默认隐藏，可取消隐藏使用。字段精确列名和顺序以下载模板为准；旧版仅 JSON 列模板仍可解析。

- 普通 C：每题一行、每选项一行；以选项组关联。选项值保留 Excel 数字/文本类型，分值为数字。每个计分指标成员一行，支持总分/维度、反向、权重、求和/平均/加权求和/加权平均及指标聚合。反向是全局逐题变换，同一道题的相反设置报冲突。
- 普通 P：每分档一行，支持已有准则阈值；参考版本默认参数组分版本。P-only 须在参数表明确填内容/计分版本。常模分布、复杂人群匹配等继续使用完整 `parametersJson`。
- 普通 R：每指标或分档一行，填写标题、解释、分档文字、建议、局限及免责声明。分档必须与选定 P 匹配。复杂图表、素材、布局等继续使用完整 `reportJson`。
- 同一量表的同一业务表选择普通行或高级 JSON 行，不混用。基本信息的 `definitionJson/metadataJson` 分别与对应普通字段互斥；`scoringJson` 与基本信息的普通计分设置互斥。同时供值直接报原始行和字段，不决定覆盖顺序。
- 同计分指标、同参数参考版本+指标、同报告指标的共享字段填在该组首行，后续留空或重复相同值；不同值报冲突。指导语和引用填纯文本，建议/局限可按换行分条。
- 默认值在“填写说明”明确列出：必答、无随机、权重 1、计分版本随本次 C、缺失策略为全部必答；授权/再分发未填则为未知。披露受众和能力均空表示不披露，不自动授予使用权。适用作答者由管理员明确填写。

- 提供 C 时，`contentVersion` 使用 `x.y.z`。高级模式题目逐行、响应集逐行、计分仅一行。`definitionJson` 包含除 `items/responseSets/scoring/report/referencePolicy` 外的现有定义字段；这五项不能在该列重复覆盖。`metadataJson` 含必需 `title`，以及可选指导语、适用性、披露、目录、本地化和既有业务元数据。
- `parametersJson` 为 `{ "referencePolicy": {…}, "references": […] }`。`reportJson` 为完整既有 report，或 `{ "definition": {…}, "template": {…}, "assetRefs": […] }`；后者保留 CHART、ASSET 等现有区块。报告组分版本须与 `reportVersion` 一致。
- JSON 单元格超过 Excel 长度限制时用 `@json:key`，在“结构片段”按相同 `toolKey/jsonKey` 及连续 `part=1,2,…` 拼接。素材必须使用既有已上传资源身份及摘要；本地文件名不能代替资源上传。
- `PROVIDED` 表示提供 P/R；`NONE` 是显式不配置，组分 payload 为 `null`；`INHERIT` 或空白表示未提供。未提供组分仅从明确的同量表 `baseCombinationId + baseCombinationHash` 继承。没有基础组合的缺项保留为草稿阻塞，不自动补 NONE 或选择 latest。
- P-only、R-only 无 C 仍可保存草稿，不能发布为可运行配置。C-only 首次配置需显式将 P/R 设为 NONE；有基础组合则可继承。

解析返回工作表、原始行号、字段路径和错误。单份错误不撤销其他有效量表。确认保存重新解析并核对预览摘要；同请求号换内容会冲突，原请求重试回读成功条目，不重复导入。修正后的文件须重新预览并使用新请求号。

## 草稿、发布和历史

草稿共用 `scale_component_drafts` 一张可编辑存储，包含精确基础组合、组分文档、revision 和导入请求凭证；没有第二套正式版本状态机。编辑核对 revision，发布事务核对 revision、精确 base、预览摘要及身份。未支持或可能被 schema 丢弃的字段明确报错。

批准沿现有 `survey_standard_versions/releases/trials` 流程，批准后源草稿冻结；试运行失败不会上线或产生个人使用权。重试使用既有记录；修改已批准/已上线内容时复制新草稿并填写新版本号。上线前普通草稿可继续编辑。

DB 导入的 C 每版本使用独立的内部 `Scale.code`，它仅用于存储寻址。业务 `toolKey/instrumentKey` 和真实 `instrumentVersion` 保持原语义；消费者通过冻结的 `scaleId` 与内容身份读取，原代码来源及 `CUSTOM_DESCRIPTIVE` 路径保留。C 的施测元数据绑定内容摘要，指导语单独变化也会产生不同 C 身份。已有代码来源的组分摘要与组合摘要算法不变。

Training 和教育入口的实际启动冻结也传递组合已绑定的导入 `scaleId`，并核对导入类型、业务键及版本；同键同版本的旧原生行不会遮蔽该来源。显式来源不存在或身份不匹配时拒绝启动，不回退到另一行。此传递不改变旧冻结快照的读取。

新 C 先以隐藏的 DRAFT 原生源物化；组合 ONLINE、部署策略和新 C PUBLISHED 在同一最终事务提交。失败整体回退。P/R-only 更新沿用既有 C，不改变旧 C 状态。正式 native 定义和已批准草稿由数据库守卫冻结。

新配置不重绑旧问卷、在途快照、授权或报告，不重算旧报告。参数和报告按精确版本组合检查，报告 release 继续绑定参数摘要。结构检查不能自动理解全部报告文案中的阈值含义，管理预览提示管理员核对对应参数及报告。

独立声明式报告模板的 `REFERENCE_BAND` 同样核对所选 P 的指标、参考类型、精确参考版本及可发出的 band key；不借用未选参数版本。缺少引用时阻止新组合发布并保留草稿，不以其他 TEXT 区块仍能显示作为兼容证据。

## 接口

以下接口挂在既有 `/api/platform/survey-standard` 认证、来源/CSRF、限流和系统管理员路由之下。

| 方法及相对路径 | 用途 |
| --- | --- |
| `GET /component-template` | 下载合成 Excel 模板 |
| `POST /component-import/preview` | multipart 文件解析和摘要 |
| `POST /component-import/save` | 文件、requestId、expectedDigest；逐项保存 |
| `GET /component-drafts?page=…` | 草稿分页 |
| `POST /component-drafts` | 建立编辑器新版本草稿 |
| `GET /component-drafts/:id` | 读取完整草稿 |
| `POST /component-drafts/:id` | expectedRevision 和完整文档 |
| `GET /component-drafts/:id/preview` | 精确拟发布组合和阻塞项 |
| `POST /component-drafts/:id/publish` | 既有批准及自动试运行 |
| `POST /component-revision-prefill` | 从精确已冻结组合复制新草稿 |

管理界面复用已有量表编辑器、报告区块编辑器及精确委托界面，高级结构可通过完整 JSON 编辑。可视化编辑器未支持的素材/图表区块保留原值；完整字段仍可通过 Excel/JSON 表达，不声称已新增可视化编辑器平台。
