## 实际实现

- 复用原 `NumberlineTrack` 点击/触控/键盘定位；只增加默认保持旧界面的可选 `showReferenceTicks`。新NP仅显示端点，移除中点/四分位刻度与中点数值，不提示分段策略；旧C默认不变。
- 一题31或310的中性点击练习，不与本范围A/B正式点重合；没有正确位置标记、反馈、15%门槛或数学策略教学。练习只熟悉输入、未进入正式记录。
- 新正式界面六题，不给正确位置反馈。每题从目标出现时用performance时钟按绝对截止时刻调度；超时为位置/RT同时null；有效端点0保留。保存false/异常锁定第一次位置和RT，仅重试同一payload；第六题确认后才结束，完成回执失败单独重试，不重交/改答案。
- 前后端同一任务内镜像生成器：原数值组按冻结seed做确定性Fisher–Yates顺序；服务端重建目标并验证位置/顺序，拒绝换题和超出冻结时限的回答。
- 新S1.1.0在题序/时限校验后复用旧空间误差核：PAE、方向偏差、≤整线10%的描述性附近比例、回应数和用时。不把两个范围合并成能力指数；RT下限仍只用于RT统计（默认300毫秒），位置有效0与没有位置的null不同。
- 新展示presentation1.1.0 / reading1.1.0；旧R逐字保留在task-local previous源。R1合成时必须保留NP专属中性说明与六点协议，不能把旧C的中点建议/8题或40题说明继承回来。
- 当前FINAL仍采用已有 `fixedCountFinalSubmission('totalTrials')`，新schema固定6，新S明确要求六题且索引连续。没有放松缺题/提前完成合同，也没改全局FINAL上限。
