# 反转：单块9次反转的现平台可行性（只读结论与下一片方案）

**现通路可承载有界、任务自行结束的连续反转，不必新建自适应平台；但现有反转C/S本身不支持该机制。** 本轮已交付的C1.1修复泄露、时限、保存和训练，不把它称为原反转机制已对齐。本文件是源码核查/方案，尚未实现或验证下面的新机制。

## 已核当前合同

- `frontend/.../pages/CognitiveRunner.tsx:505`：`completionMode==='task'` 时不会按config.totalTrials自动结束；进度描述实际记录数，任务调用onTaskComplete。当前反转已用task完成模式。当前所查源码没有名为plannedTrials的独立字段，实际是界面的totalTrials显示与后端FINAL预算/任务评分完成条件三者分工。
- `backend/.../v2/final-submission-budget.ts`：配置解析/冻结时计算精确版本拥有的maxTrials，上界不能超过既有1000；`trial-normalizer.ts`检查1..maxTrials。这里是**上界**，不是要求必须提交满max。
- `backend/.../v2/session-snapshot.ts`：config、C/S、协议与seed上下文冻结；`authoritative-scorer.ts`核同身份、配置、连续trialIndex、持久化phase及audit实际数量，再调用任务scorer；`completion.service.ts`/两条FINAL都走权威评分，未提供通过客户端声明阶段来绕过的出口。
- 现`scoring/reversallearning.v1.ts`严格要求固定totalTrials及前后两段，不能把criterion从6改10就伪装成累计正确触发。既有`scoring/corsi.v1.ts`则已有任务内重放、验证终止且拒绝终止后多交题的先例，说明无需改共享FINAL完整性合同。
- 当前readiness明确学习/自适应状态不能由trialIndex安全重挂，采用restart-required；taskContext没有通用历史状态输入。新串行任务应沿用该策略，不能擅自标safe-resume、仅靠最大索引恢复或让G1另建checkpoint平台。本轮未碰G1共享文件。

## 最低可实施任务片

1. 新建独立C1.2/S1.2/P1.2（版本号为方案占位，实施时核实际已用身份），保留现C1.0/C1.1。单块10个鉴别阶段，即9次反转；任务内纯函数由冻结seed和已确认choices重放当前阶段、当前正确符号与累计正确数。
2. 每阶段冻结10–15次正确选择阈值，**累计且包括收到误导负反馈的正确选择，不是连续正确**。达到阈值后翻转符号；最后阶段达标才结束。错选/遗漏不增加正确数，展示与服务器重放使用同一任务规则，客户端不决定阶段或正确键。
3. 按原方法设计0–4次/阶段的受控误导性负反馈，保留一次相邻误导负反馈安排，替换当前独立Bernoulli默认0.8；错选不因此获得20%奖励。论文未公开完整作者程序/逐题序列，如何在错选插入时安排那一对误导需要显式定义、冻结和披露数字适配规则，不能声称作者原序列已知。无须引入第三方80/20模型。
4. 继续复用现2秒正式窗、500毫秒反馈调度下限、30题无反转训练、独立练习图形、首次答案锁定/保存重试。训练步速与网页/扫描器差异仍明确，不搬三块扫描实验或3253毫秒采样节拍。
5. 预算用任务自身冻结maxTrials（≤1000），而非伪造已完成试次数；现FINAL工厂可表达这个上界。新S重放验证恰在10阶段终点结束，拒绝提前FINAL、遗漏中间索引、阶段伪造和终止后多交题。预算耗尽但未达9反转时**不按完成评分**，保留已写原始记录，沿现有未完成/放弃生命周期处理；不把“到上限”改成研究已完成，也不放宽全局上限。具体上限是数字适配的操作边界，不能冒称来自论文。
6. 仅任务内generator/state reducer、config、scorer、runner、seed/semantics/报告和task-package；共享生成表按既有流程。新原始payload可以继续保存choice/RT/interrupted，阶段/反馈由服务端重放导出，无须数据库schema或通用实验平台。新报告列实际完成阶段/反转数、选择和反馈记录，不输出人格/能力等级。

## 尚未达成、供母DOT统筹

本轮尚未实现新阶段重放、新S、受控误导序列和预算耗尽流程，也未验证其四入口。当前C1.1仍固定一次反转。真实最低验证应是几条任务内轨迹：累计正确含概率错误、错选/遗漏不增加、连续反转直到第9次、提前/多交/伪阶段拒绝、保存失败不推进状态；加一个很短组件轨迹即可，不需要全平台CI或新资格链。G1/D需接入新精确身份的既有readiness，原门禁/完整性合同不变。
