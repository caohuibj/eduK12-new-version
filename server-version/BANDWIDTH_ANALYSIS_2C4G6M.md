# 2核4G6M 服务器视频并发能力分析

**配置**: 2核CPU / 4GB内存 / 6Mbps带宽 / 无CDN  
**场景**: 教学视频播放 (720p/480p)  
**分析日期**: 2025-02-07

---

## 📊 基础数据换算

### 带宽换算
```
6 Mbps (理论) = 768 KB/s
实际TCP损耗后 ≈ 600-650 KB/s (约80%效率)

计算基数:
- 可用带宽: 600 KB/s (保守估计)
- 突发带宽: 700 KB/s (峰值)
```

### 视频码率标准

| 分辨率 | 推荐码率 | 实际码率 | 流量消耗 |
|-------|---------|---------|---------|
| **480p** | 800 kbps | 100 KB/s | ~0.35 GB/小时 |
| **720p** | 1200 kbps | 150 KB/s | ~0.53 GB/小时 |
| **1080p** | 2500 kbps | 313 KB/s | ~1.1 GB/小时 |

## 🎯 纯视频流并发计算

### 理论最大并发

#### 480p 视频
```
可用带宽: 600 KB/s
单路480p: 100 KB/s

理论并发 = 600 ÷ 100 = 6 路

考虑20%冗余(网络波动): 6 × 0.8 = 4-5 路
```

#### 720p 视频
```
可用带宽: 600 KB/s
单路720p: 150 KB/s

理论并发 = 600 ÷ 150 = 4 路

考虑20%冗余: 4 × 0.8 = 3 路
```

### 实际场景并发

实际应用中，用户不只是看视频，还需要：
- 加载网页 (HTML/CSS/JS)
- API请求 (课程列表、用户信息)
- 图片浏览
- 其他资源

#### 带宽分配建议
```
总带宽: 600 KB/s

分配:
├── 视频流: 70% = 420 KB/s
├── API/动态: 20% = 120 KB/s
└── 静态资源: 10% = 60 KB/s
```

#### 实际并发能力

| 分辨率 | 视频带宽 | 单路消耗 | 并发路数 | 实际推荐 |
|-------|---------|---------|---------|---------|
| **480p** | 420 KB/s | 100 KB/s | 4.2 路 | **3-4 路** |
| **720p** | 420 KB/s | 150 KB/s | 2.8 路 | **2-3 路** |

## 📈 混合场景分析

### 典型教学场景

**场景A: 直播/实时课堂**
```
用户行为:
- 40人在线
- 30人观看视频 (主要瓶颈)
- 10人浏览图文

带宽需求:
- 视频: 3路480p = 300 KB/s
- 其他: 40人 × 5 KB/s = 200 KB/s
- 总计: 500 KB/s ✅

结论: 支持40人在线，其中3人同时播放视频
```

**场景B: 录播/自主学习**
```
用户行为:
- 60人在线 (非同时播放)
- 峰值5人同时播放
- 大部分在看课件

带宽需求:
- 视频峰值: 5路480p = 500 KB/s
- 其他: 60人 × 2 KB/s = 120 KB/s
- 总计: 620 KB/s ⚠️

结论: 勉强支持，建议限制为4路视频
```

**场景C: 纯视频播放测试**
```
只播放视频，无其他操作:

480p: 6路 (理论) → 4路 (实际推荐)
720p: 4路 (理论) → 3路 (实际推荐)
```

## ⚠️ 其他瓶颈分析

### 1. CPU 瓶颈

```
视频转码 (非播放时):
- 2核CPU最多支持1路视频转码
- 转码时无法处理播放请求
- 建议: 夜间批量转码

视频播放 (仅传输):
- 纯文件传输不占用CPU
- Node.js可以支持50+并发连接
```

### 2. 内存瓶颈

```
4GB内存分配:
├── 系统占用: 500MB
├── PostgreSQL: 800MB
├── Node.js: 400MB
├── 文件缓存: 500MB
└── 可用: 1800MB

视频播放内存占用:
- 每个连接: ~10MB
- 理论支持: 1800 ÷ 10 = 180 连接

结论: 内存不是瓶颈，带宽才是
```

### 3. 磁盘 I/O

```
SSD 70GB:
- 视频读取: 顺序读，SSD轻松支持
- 支持100+并发读取

结论: 磁盘不是瓶颈
```

### 4. 月流量限制

```
月流量: 600GB

480p场景:
- 每路: 0.35 GB/小时
- 4路并发 × 8小时/天 × 30天 = 336 GB ✅

720p场景:
- 每路: 0.53 GB/小时
- 3路并发 × 8小时/天 × 30天 = 381 GB ✅

结论: 600GB月流量足够
```

## 🎯 最终结论

### 无CDN情况下的最大并发

| 场景 | 480p | 720p | 备注 |
|-----|------|------|------|
| **纯视频流** | 4-6路 | 3-4路 | 仅视频，无其他 |
| **混合教学** | 3路 | 2路 | 包含API/图片等 |
| **峰值突发** | 5路 | 3路 | 短时间内可承受 |
| **稳定运行** | 3路 | 2路 | 长期推荐配置 |

### 推荐配置

**低配模式 (推荐)**:
```yaml
视频分辨率: 480p
视频码率: 800kbps
并发限制: 3路
月流量: ~350GB (安全范围)
支持用户: 40人在线，3人同时播放
```

**标准模式**:
```yaml
视频分辨率: 720p
视频码率: 1200kbps
并发限制: 2路
月流量: ~380GB (安全范围)
支持用户: 30人在线，2人同时播放
```

## 💡 优化建议

### 1. 必须启用COS+CDN

**为什么必须:**
- 6M带宽传视频是致命瓶颈
- CDN后带宽压力降低90%
- 支持并发从3路提升到30路+

**成本对比:**
```
无CDN:
  - 带宽: 6M
  - 并发: 3路480p
  - 体验: 卡顿，不可用

有CDN:
  - 带宽: 6M (只传API)
  - 并发: 30路+ (CDN分流)
  - 体验: 流畅
  - 成本: +¥50/月
```

### 2. 自适应码率

```typescript
// 前端根据带宽选择清晰度
const getOptimalQuality = (bandwidth: number): string => {
  if (bandwidth < 1000) return '360p'  // 1Mbps以下
  if (bandwidth < 2000) return '480p'  // 2Mbps以下
  return '720p'
}
```

### 3. 预加载控制

```typescript
// 限制预加载，节省带宽
video.preload = 'metadata'  // 只加载元数据
// 或
video.preload = 'none'      // 点击后加载
```

### 4. 流量削峰

```yaml
限制同时播放:
  - 高峰期限流3路视频
  - 队列等待机制
  - 提示用户"当前观看人数较多"
```

## 🆘 应急方案

**带宽超标时:**
1. 立即降级到480p
2. 限制并发为2路
3. 提示用户"网络繁忙"
4. 启用队列等待机制

**长期解决方案:**
1. 升级带宽到10M (+¥100/月)
2. 或启用CDN (+¥50/月，效果更好)

---

**总结**: 
- 无CDN时，6M带宽只能支持 **3路480p** 或 **2路720p**
- **强烈建议启用CDN**，否则视频功能几乎不可用
