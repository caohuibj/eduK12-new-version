# 家长端与组织成员支持：实现和上线执行手册

日期：2026-10-04。适用分支：`fix/organization-parent-portal`。本次在本地隔离数据库验证；没有修改 eduk12.top 生产账户、成员关系或配置。

## 1. 为什么原先无法开放

后端以 `PARENT_PORTAL_ENABLED=false` 为默认配置。关闭时 `/api/capabilities` 返回 `parentPortal:false`，亲子关联、孩子报告、家长报告发布 API 返回 404。此前 Web 主要提供家长本人的测评，没有完整的账号建立、孩子列表、逐份报告授权和负责人发布页面。直接打开开关不能完成学校实际使用流程。

现有后端已经提供亲子关联、学生同意、独立披露授权、冻结报告、工具版本上限、撤回和审计。本次复用这些合同，补齐操作入口和组织学生邀请来源。普通账号的名字叫 `admin` 或 `User.role=ADMIN` 都不等于当前 `platformRole=SYSTEM_ADMIN`。

## 2. 已实现能力

| 场景 | 页面和行为 |
| --- | --- |
| 平台建立家长账号 | `/parent-accounts`；服务端搜索、分页、创建、重置密码、启停。创建和重置需要当前 SYSTEM_ADMIN。初始密码由管理员输入/浏览器生成，首次登录强制改密；不在响应、回执、审计中保存明文。 |
| 工具披露设置 | `/parent-tool-policies`；按 family/key/version 读取并设置 NONE、COMPLETION_ONLY、INDIVIDUAL_SUMMARY。使用版本号和命令回执，发生冲突必须重新核对。 |
| 学生邀请家长 | `/student/parent-links`；可选择当前有效组织 STUDENT 工作身份或兼容旧课程。亲子邀请码15分钟、一次使用、仅哈希存储。 |
| 家长提出关联 | `/parent/links`；填写学生提供的24位邀请码；申请本身不授予孩子和报告访问。 |
| 学生确认与撤回 | 核对具体家长并确认服务端说明；可以解除关系或逐份撤回报告授权。 |
| 家长孩子和报告 | `/parent/children`、`/parent/children/:childId`、`/parent/children/:childId/reports/:artifactId`；分页、多孩子切换、空态、错误恢复、只渲染 PARENT 投影。 |
| 负责人工作台 | `/organizations/:organizationId/parent-reports`；选择当前可用模板、预览、明确发布、查看学生有效同意、逐份授权。 |
| 组织成员管理 | 组织概览内服务端分页、搜索、角色/当前/历史筛选、显示姓名及用户ID、原子建立成员及可选工作身份、角色调整、结束关系、授权历史、能力授予/撤销。 |
| 自助加入组织 | 管理员产生24小时有效的一次成员邀请码；成员登录后在 `/organization-invitations` 核对组织和身份再接受。邀请仅建立 MEMBER，不授予 ORG_ADMIN、导出或家长报告披露能力。 |
| 组织访问诊断 | `src/scripts/diagnose-organization-access.ts`；只读事务输出账户状态、平台身份、当前组织关系、工作身份、能力、拒绝条目。 |
| 小程序兼容 | 学生也可以选择组织来源生成亲子邀请码；原课程邀请合同保持兼容。 |

家长在具体报告页可点击“停止查看本份报告”，核对确认后只撤回该关系下该份报告；亲子关联与其他报告授权保留。学生同样可逐份撤回；解除关联则停止该关系的后续访问。

组织治理的当前成员选择器、学生/教师关系历史和投放授权读取完整分页；数据变动、缺页或加载失败会明确提示并提供原页重试。离开页面后迟到回调不再跳转或恢复旧组织状态。

身份切换、资源切换和页面重新获得焦点时重新读取权限。过时异步响应不能恢复另一账户的报告；撤回后当前页面清除旧内容。首页、登录页和业务页区分“确认关闭”和“开关读取失败”，后者提供重试。

## 3. B1 的具体解决方法

目标组织：`1410be7c-18e3-4f8c-a0f0-0f190088f08d`。生产数据库尚未独立核实，不能把旧验收中的账号名称当作已经具备任何权限。

先用具备数据库只读访问的运维账户执行诊断，连接字符串通过受保护环境注入，不写入命令历史或报告：

```sh
# 在 server-version/backend 执行；DATABASE_URL 必须已明确设置
npx tsx src/scripts/diagnose-organization-access.ts \
  --organization-id 1410be7c-18e3-4f8c-a0f0-0f190088f08d \
  --username admin
```

按结果处理：

1. 组织不存在：核对目标ID和所连环境。组织暂停：由有权平台管理员恢复后再测试。
2. 账号停用、冻结、到期、首次改密或教师未审批：先走对应账号流程。不能用新成员关系绕过这些状态。
3. `platformRole=STANDARD` 且无当前成员关系：没有组织权限属于正常拒绝。由现有可用 ORG_ADMIN 或当前 SYSTEM_ADMIN 进入目标组织，将验收账号加入。
4. GUI 路径：组织空间 → 目标组织 → 成员关系 → 新增成员。平台管理员可搜索账号并选取ID；组织管理员可用精确ID，也可产生成员邀请码让已有账号登录接受。
5. 视觉验收只需要当前有效 MEMBER。教师投放需另行授予相应组织工作身份并满足投放合同；报告负责人需 `PARENT_REPORT_DISCLOSURE` 和具体来源读取权限。普通 ORG_ADMIN 或 SYSTEM_ADMIN 均不自动获得所有个体报告权限。
6. 有显式拒绝时，先由获授权的管理流程核对、解除对应拒绝，再重试；新邀请不会消除拒绝。
7. 成员接受邀请后刷新组织目录，确认顶部组织选择器、目录和目标概览使用相同ID，再执行 B1 视觉复验。

如果没有任何可用 SYSTEM_ADMIN，且目标组织也没有可用 ORG_ADMIN，则属于平台权限恢复，需要部署负责人核实授权并按独立、可审计的恢复程序处理。重复运行 seed 不会重新提升已经被降权的旧管理员。本次没有编写自动提权或自动将所有 admin 加入组织的脚本。

组织成员关系结束后保留历史；再次加入建立新ID。必须至少保留一位可用组织管理员。创建组织的首位管理员，以及新增/提升 ORG_ADMIN，均要求目标账号已完成改密、教师审批并可用。已有组织内的治理拒绝（`*` / `ORGANIZATION_GOVERNANCE`）使其不能充当可用管理员；结束或降级成员时也不把这类账号计作可用替代。其他独立能力拒绝不改变治理统计。邀请人失去治理权限、组织暂停、邀请码过期/撤销、领取者不匹配所选教师/学生身份或存在整体拒绝时，邀请不能被使用。

## 4. 家长端学校操作顺序

1. 确认一位可用 SYSTEM_ADMIN。建立组织管理员和学生成员。只有组织 STUDENT 工作身份且 `User.role=STUDENT` 的有效学生才能用组织来源邀请家长。
2. 平台管理员通过家长账号管理建立 PARENT 账号，妥善交付初始密码。家长首次登录改密并重新登录。账号管理可在门户关闭时预先配置。
3. 平台管理员按正式工具的精确版本设置披露上限；初次试运行建议只允许 COMPLETION_ONLY。新版本默认 NONE。
4. 在组织成员授权详情中为负责人单独授予家长报告披露能力，并按实际报告政策配置来源读取资格。能力本身不能绕过来源授权。
5. 生成受支持的正式组织报告。当前发布流程支持 PROTECTED_FEEDBACK 和 INDIVIDUAL_LONGITUDINAL；不会把任意课程作业、学生原始作答或普通未注册报告转为家长内容。
6. 学生生成邀请码 → 家长提交申请 → 学生核对确认。家长可看到已确认孩子，但仍不能读取任何未获准报告。
7. 负责人在家长报告工作台选择模板并预览，明确发布这个版本。学生在家长关联中逐份预览、勾选说明并同意。负责人核对接收家长后逐份授权。
8. 家长读取获准的 PARENT 版本。学生撤回某份报告只影响该份报告；解除关联影响该关系的所有新访问。已经下载或截图的外部副本不能由系统追回。
9. 解除后重新绑定必须使用新邀请码、学生再次确认和新的逐份报告同意/授权；不会复活旧证据。

## 5. 模板与科学内容边界

正式默认模板只有 `parent-report-availability@1.0.0`，展示报告已生成和完成情况。本次没有为任何生产工具编造科学解释、分数等级或教育建议。

新增教育摘要通过独立内容变更加入 `src/modules/parent-portal/reviewed-templates.ts`。每条须有精确 toolRef、不可变模板版本、正式来源 metricId/sourceMetricKey 映射、允许的聚合/纵向规则、家长能理解的标签和经审核的免责声明。登记后必须经过：注册表校验、来源 spec 指标匹配、来源读取授权、隐私门槛、工具披露上限及模板投影测试。已发布版本不能覆盖修改，修订必须增加版本。

目前渲染器只转述正式来源中允许披露的值、缺失波次和服务端准许的变化值，不在家长端重新评分或生成解释。科学解读材料的审核仍由内容负责人完成。

## 6. 数据迁移与发布顺序

两次迁移：

- `20261004000100_parent_relationship_episodes`：把亲子配对的全历史唯一改为 PENDING/ACTIVE 当前关系唯一；保留历史ID和所有报告外键；邀请码新增组织+精确成员关系来源，与旧课程来源互斥。
- `20261004000200_organization_member_invitations`：一次组织邀请、哈希码、截止时间、消费者和成员关系外键、状态一致性检查。

生产操作须由部署负责人按现有发布流程执行：

1. 建立并验证数据库备份，确认当前 migration 状态；保持家长开关 false。
2. 执行现有 `npm run db:migrate:guarded`，再 `npm run db:generate`；部署新后端及前端资源，避免旧后端继续按全历史唯一读取亲子关系。
3. 核对组织访问诊断，先完成 B1 成员配置和视觉验收。配置家长账号、负责人能力、正式工具上限及报告。
4. 将部署环境 `PARENT_PORTAL_ENABLED=true` 注入后端并重启。hardened compose 已传递此变量；使用其他部署方式时核对变量实际进入运行容器。
5. 检查 `/ready` 和 `/api/capabilities`，后者须返回 `parentPortal:true`。核对前端资源指纹和后端发布版本，不能仅根据 Git 分支判断线上已更新。
6. 按第4节完成一次真实学校小范围闭环，使用独立浏览器会话。复验错误身份、无同意、撤回、关系结束、来源权限取消、账号冻结和工具上限收紧。
7. 观察 401/403/404/409/429/503 和审计。组织邀请或账号创建遇到不确定结果时先核对列表，不自动重放新邀请。账号和发布的精确命令回执支持同一输入重试；版本冲突需重新预览。

快速关闭家长报告业务：恢复开关 false 并重启后端；或精确收紧工具上限。只切开关不撤销历史关系或证据。开关不控制管理员的账号预配置及独立组织成员管理。数据库迁移回退需先核对是否已经产生同一亲子的多个历史关系，不能直接恢复原全历史唯一索引，也不能盲目降级到旧后端。

## 7. 验证证据和复跑

本地 PostgreSQL16、独立命名测试库、UTC时区；全部99次迁移已成功应用。集成测试需要显式指定测试连接：`DATABASE_URL` 与 `RELEASE_INTEGRATION_DATABASE_URL` / `PARENT_PORTAL_TEST_DB_URL` 指向同一个隔离测试库。数据加密密钥使用测试专用值，不使用生产密钥。

```sh
# backend：在已迁移的隔离测试库上串行运行

  src/__tests__/integration/parentPortal.postgres.integration.test.ts \
  src/__tests__/integration/miniprogramParentHttp.postgres.integration.test.ts \
  src/__tests__/integration/miniprogramPublicationHttp.postgres.integration.test.ts \
  --maxWorkers=1 --no-file-parallelism

# 实际 Chrome 网页验收：先构建 frontend/dist，仍使用隔离测试库
DOTQA_BROWSER_E2E=true npx vitest run \
  src/__tests__/integration/parentOrganizationBrowser.postgres.integration.test.ts \
  --maxWorkers=1
```

浏览器测试不替换业务 API，使用实际 Cookie、CSRF、PostgreSQL、发布的冻结报告，并为管理员、学生和家长使用独立 BrowserContext。桌面1440和移动视口390完成整个账号、绑定、发布、同意、授权、读取及撤回流程；移动视口不等同于真实手机测试。

另有前端资源隔离/开关/显式同意测试、组织邀请并发和失效测试、亲子重新绑定不继承旧报告授权测试、小程序静态及运行时测试。组织访问诊断没有生产数据输出，本轮仍需部署后为指定生产组织实际配置账号才能关闭 B1。
