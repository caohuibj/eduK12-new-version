# 2核2G3M 服务器并发性能分析报告

**配置**: 2核CPU / 2GB内存 / 3Mbps带宽  
**测试基准**: PTool教学管理系统 (已优化版本)  
**分析日期**: 2025-02-07

---

## 📊 硬件资源分析

### 资源换算

| 资源 | 数值 | 说明 |
|-----|------|------|
| **CPU** | 2核 | 约 4000 单核评分 (云服务器) |
| **内存** | 2GB | 实际可用约 1.6GB (系统占用) |
| **带宽** | 3Mbps | 理论下载 375KB/s |
| **磁盘** | 标准云盘 | 约 100-150 IOPS |

### 理论并发计算

```
并发用户数 = min(CPU限制, 内存限制, 带宽限制)

【CPU限制】
- Node.js单线程，但可处理异步IO
- 2核 ≈ 可处理 30-40 个活跃请求
- bcrypt等计算密集型: 10-15 并发

【内存限制】
- 可用内存: 1.6GB
- 单个用户会话: ~30MB (含文件上传缓存)
- 理论上限: 1.6GB ÷ 30MB ≈ 53 用户
- 实际安全上限: 30-40 用户

【带宽限制】⚠️ 最大瓶颈
- 3Mbps = 375KB/s
- 页面加载 (HTML+CSS+JS): ~500KB
- 并发页面加载: 375÷500 ≈ 0.75 用户
- 即: 几乎只能串行加载页面

【图片加载】
- 单张图片: 100KB
- 并发: 375÷100 ≈ 3-4 张/秒
- 即: 3-4人同时刷图会卡顿

【视频播放】❌ 不可用
- 标清视频: 500KB/s
- 3Mbps ÷ 500KB/s = 0.75
- 结论: 无法流畅播放视频
```

## 📉 性能瓶颈层级

### 瓶颈排序 (从高到低)

| 排名 | 瓶颈 | 影响 | 占比 |
|-----|------|------|------|
| 1 | **带宽 3M** | 页面加载慢、视频不可用 | 60% |
| 2 | **内存 2G** | 用户过多时OOM | 25% |
| 3 | **CPU 2核** | bcrypt计算慢 | 15% |

### 详细瓶颈分析

#### 1. 带宽瓶颈 ⚠️ 致命

```
问题描述:
- 3Mbps = 375KB/s 理论速度
- 实际TCP损耗后: ~300KB/s
- 现代网页平均: 1-2MB

实际体验:
├── 首次加载: 5-10秒
├── 图片加载: 2-3秒/张
├── 多用户同时: 10-30秒
└── 视频播放: 无法缓冲

计算示例:
页面大小: 800KB (HTML+CSS+JS+图片)
下载时间: 800÷300 ≈ 2.7秒
10人同时: 27秒 (串行)
```

#### 2. 内存瓶颈 ⚠️ 中等

```
内存分配:
├── 系统占用: 400MB
├── PostgreSQL: 300MB
├── Nginx: 50MB
├── Node.js基础: 150MB
└── 可用给用户: 1.1GB

用户内存占用:
├── 基础会话: 8MB
├── 文件上传缓存: 20MB
├── 数据库连接: 5MB
└── 总计: ~33MB/用户

计算:
1.1GB ÷ 33MB ≈ 33 用户
安全阈值 (80%): 26 用户
```

#### 3. CPU瓶颈 △ 轻微

```
CPU使用场景:
├── bcrypt密码验证: 50-100ms (高CPU)
├── JSON序列化: 5-10ms
├── 数据库查询: 10-30ms (IO等待)
└── 业务逻辑: 5-15ms

并发处理:
- Node.js事件循环可并发处理IO
- 计算密集型任务会阻塞
- 2核可并行处理2个计算任务

计算能力:
- 纯API请求: 40-50 并发
- 含登录: 20-30 并发
```

## 💡 优化方案

### 方案A: 不做改变 (裸跑)

```
适用场景:
- 10人以下小班级
- 纯文字教学
- 非高峰时段使用

限制:
- 不能传图片/视频
- 不能多人同时操作
- 高峰期会卡顿

成本: ¥100/月
推荐度: ⭐⭐ (仅测试用)
```

### 方案B: 必须优化 (推荐)

```
优化措施:
1. 压缩所有静态资源
2. 启用Gzip压缩
3. 浏览器缓存7天
4. 图片压缩后上传 (<100KB)
5. 禁止视频播放
6. 分页加载 (每次10条)

收益:
- 页面大小: 800KB → 200KB
- 并发能力: 15人 → 25人
- 用户体验: 可用 → 良好

成本: ¥100/月 (不变)
推荐度: ⭐⭐⭐⭐
```

### 方案C: 使用COS (强烈推荐)

```
架构改变:
用户 → CDN → COS (静态资源)
     → 服务器 2C2G3M (API)

资源分流:
- 图片/视频: 走COS (不占用3M带宽)
- API请求: 走服务器

收益:
- 带宽压力: 降低 90%
- 并发能力: 25人 → 40人
- 视频播放: 不可用 → 流畅
- 用户体验: 接近4C8G效果

成本:
- 服务器: ¥100/月
- COS: ¥30/月 (100GB存储+流量)
- CDN: ¥20/月 (500GB流量)
- 合计: ¥150/月

推荐度: ⭐⭐⭐⭐⭐ (最佳性价比)
```

### 方案D: 升级配置

```
升级到 2C4G5M:
- 内存: 2G → 4G (100%提升)
- 带宽: 3M → 5M (67%提升)

收益:
- 并发能力: 25人 → 50人
- 视频播放: 1路标清

成本: ¥200/月 (+¥100)
推荐度: ⭐⭐⭐⭐ (如果不差钱)
```
