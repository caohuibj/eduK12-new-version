# C14 cold Form FINAL / outbox harness

This is a bounded correctness extension on a byte-verified stopped FULL02 clone.
It does not qualify browser behavior, latency, CPU capacity, or load.

## Why null-policy Form

A weighted-variant FINAL resolves selected scope, reading FSP2 before its write
transaction. It cannot isolate a cold outbox FSP2 read. This fixture intentionally
uses an ordinary null-policy Form-only published questionnaire on an existing
real Training course, with six new UUID synthetic students and normal HTTP starts.
No existing answers, allocations, immutable ciphertexts, or runtime code are edited.

After those starts have persisted UAR2 admissions and FSP2 references, the wrapper
SIGTERMs its owned API, verifies exit/closed port, and starts the identical runtime
and environment on the same port with a new PID and separate log. The original
report worker stays running. Submit phase performs auth calls only before six
concurrent first FINALs, and never calls start/state/whole endpoints beforehand.
Health, ready, and metrics do not resolve assessment templates.

Source path audit:
- `training-variant-child-scope.ts` returns null scope for complete LEGACY markers.
- `form-admission.service.ts` uses the already stored UAR2 admission. Its unit plan
  hash differs from the FSP2 slot plan hash, asserted in prepare.
- `unified-form-section-final-submit.service.ts` persists answers and canonical
  snapshot in the original transaction.
- The canonical snapshot outbox hook loads FSP2 via its supplied transaction;
  the six-request observer uses a separate process pool and identifies API PG
  connections by owned socket inode/client port. It never queries API metrics
  during the concurrent window.

FSP2 placement is an inference from the fixed source path and restart/route evidence.
The PG PUBLIC_TEMPLATE query class does not distinguish FSP2 versus UAR2 hashes.

A separate restricted-runtime PG connection locks all six new parent rows. Only
when the observer has witnessed six API-owned in-transaction Lock waiters blocked
by that gate does it release the gate in one commit. A three-second safety release
cannot qualify the barrier; missing simultaneous wait evidence fails the run.
The gate transaction has its own bounded lifetime; it does not extend API timing.
Pool limit remains six and transaction timeout remains its original five seconds.
A successful run requires all six first ACKs, one answer/canonical fact per parent,
one READY original-worker job with attemptCount=1 each, unchanged frozen controls,
unchanged old Form/canonical facts and other-tool/quota counts. PG wait states and
CPU observations are diagnostic only. No artificial RNG, cache injection, database
mutation of admitted state, or timeout increase is used.

## Additional read-only checks

Prepare inspects FULL02's original fixture student's main product: three legal
attempts (COMPLETED, ABANDONED, COMPLETED), exact selected children, and source-bound
Cognitive quota counts matching only those sessions. This is post-hoc consistency,
not an instantaneous before/after six-start census.

Owner `GET /composite-assessments/:id/export/preview?detail=full` reuses completed
FULL02 inputs. The route returns sampled field metadata, no rows. Assert one
sample, full detail, total completed count, variant fields/stratum metadata, and
other-teacher denial. Existing CSV/ZIP and builder tests retain value-level
NOT_SHOWN/blank evidence; this preview check does not invent absent row values.

Static checks: Node v24.21.0 `--check`, Python AST parse; actual execution is owned
by the parent runner. Qualification is only after recorded runtime success and
cleanup. Existing successful restore is inherited with its own source identity,
not rerun or attributed to this new cold-final phase.
