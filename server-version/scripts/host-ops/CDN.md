# Existing media CDN viewer boundary

`cdn.py` changes only Authentication for `cdn.eduk12.top`. Default `inspect` is read-only. `prepare --state <private-root-owned-directory>` saves the exact old authentication configuration and one generated candidate. `apply` compares the old configuration hash before changing it; it cannot switch authentication off or exempt file types. Every file requires SHA-256 Type D authentication with a 600-second window. Credentials remain in server memory; configuration and generated key remain root-only. No origin target, DNS, TLS, COS policy, application image, database or backup setting changes. `cdn-origin.cjs` separately changes the media bucket canned ACL from owner + AllUsers READ to owner-only private. It refuses custom grants and changed fingerprints; backup bucket configuration is outside its fixed target. Keep the before ACL as root-only configuration rollback evidence.

Before applying, confirm the current application emits authorized asset capabilities and legacy static uploads are disabled. Current migrated business records use their original logical asset IDs and parent authorization, followed by native COS short-lived URLs. Viewer CDN credentials are not passed to the application. Public checkin and frozen assessment media keep their existing scoped capability paths. Old unsigned CDN URLs must reject anonymous users; they are not public compatibility URLs. Stored legacy business records continue through their migrated asset IDs. Historical import previews are not live media consumers.

Validate anonymous GET/HEAD/Range against old and migrated paths, encoded path and malformed/expired signatures; a valid bounded CDN signature is a control only. Also validate authorized application issuance and native COS Range content, permission rejection, and active legacy video playback. Keep configuration rollback evidence, but do not restore anonymous access as a convenience rollback. On compatibility failure retain media and fix the affected authorized path before deleting copies. No load test is needed.

Retiring old media is a separate explicit operator action after fresh all-table reference review, current object metadata/content/backup binding, confirmation that old-prefix writers are disabled, and canonical content retained. Do not merge active StoredAsset identities or modify their ownership. Do not delete backup objects or original format variants with a different digest. No automatic media deletion or additional timer is installed.
