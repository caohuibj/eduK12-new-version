# 认知测验审计、优化与入库

规范版本 0.1.2。仓库 caohuibj/eduK12-new-version。先读 [唯一工作流规范](references/workflow.md)。[单项记录](assets/instrument.json) 和 [批次记录](assets/batch.json) 是 AI 工作记录，不是新的后端 payload 或准入门禁。

## 本次执行边界

先确认任务是工作流设计、设计审核、已有工具审计修复，还是指定环境的安装发布。只搭建工作流时不运行测验验收、安装预览、数据库操作、CI或部署。技能文件本身不授予这些权限。缺环境连接时仍可完成来源核对、方案与可移交内容，但不能声称运行或入库成功。

已有工具先读当前远端、工作区、AGENTS.md、docs/release/README.md，核对已完成版本、暂停WIP和证据。每项共用一套测验实现，research/experience 是两个冻结参数配置，主要差异为重复次数；不为两个profile或四个入口复制测验。其他实际差异显式审阅，不抹成“完全一致”。

实际 CI 选择、命令副作用与 browser/native 边界见仓库 [认知入库 CI 合同](../../../docs/development/cognitive-intake-ci-20261029.md)。Project 包必须携带固定来源 commit；不以默认分支的可变链接替代执行版本。

## 四步

1. 收集与去重，核定稳定key、来源、已有方案批准、三轴版本及双profile；关联现有Notion工具记录。资料或代码不足时明确是设计/资料候选，不冒称完整工具。
2. 审计并优化 C 测验与计分、P 参数参考、R 报告。认知额外审计真实设计与视觉交互、启动说明、例子和练习。先指出具体问题再最小修改。重要测量设计变动遵循已有图审确认；普通工程修复不重复审批。
3. 执行与差异相称的最小验证，复用同输入合格证据。共享运行器测一次；两个profile分别证明次数、条件与参数绑定；确有差异的输入和权限边界分别证明。只读JSON不构成视觉或实机通过。
4. 在明确授权及目标能力范围内提交、安装、发布并回读，分别记录。只安装为DRAFT/GRANT不叫公共发布；目标环境未加载版本时停在待安装，不擅自部署。

报告温暖、易懂、有信息量，图表反映真实数据。不可编常模、诊断、职业预测或0–100能力分。缺失null与0区分；中断不伪报完成；报告文字、图表、下载遵循同一三态和公开投影。科研原件归档与轻量报告保存分别记，不为偶发帧偏差增加强制预检、重测或COS回算。

批量失败逐项隔离。已有证据只因相关实现、配置、素材、迁移、环境或依赖变化而失效。写入不确定先回读，不盲目重试。Notion失败保留待同步，不让记录系统阻断内容处理。
