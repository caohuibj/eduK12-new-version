# EDUK12 量表审计与入库

规范版本：1.0.0。目标仓库：caohuibj/eduK12-new-version。

先读 [工作流规范](references/workflow.md)，它是此技能唯一维护的业务规范。批次和单项记录分别使用 [batch.json](assets/batch.json) 与 [instrument.json](assets/instrument.json)。模板是 AI 工作记录，不是后端 payload 或新准入 schema；实际入库包必须匹配当前仓库合同。

## 接收与执行边界

接受单个或批量 PDF、Word、表格、条目文本、JSON、源码路径、PR 或固定提交链接。最低输入为条目和基本信息；缺阈值、报告不构成自动阻塞。没有文件字节时先读取/下载并核实，不能从附件名或预览宣称已看全文。

每次建立本批输入与范围：工具清单、原始输入 hash、工作流版本、仓库 SHA，以及用户允许到审计打包、Git 提交、还是指定环境入库。从本次对话或已有明确授权读取范围，不重复询问已提供事项。目标环境、正式写入身份等确实缺失时，先完成不依赖它们的内容工作，不猜生产地址或借管理员身份。

运行环境有仓库时先读 AGENTS.md、docs/release/README.md 和受影响路径规则。对话不能访问仓库/系统时，完成能证明的审计与可移交文件，明确结构适配/执行/安装哪些尚未验证。技能被调用或可见不等于已经获得写库、上传、合并、部署或授予访问权的许可。

## 四步处理

1. 收集、补查、去重，关联 Notion 原记录；没有记录则在已确定的工具库父页登记。没有 Notion 连接时保留本地待同步记录并继续，不重复创建页面或声称已同步。
2. 按规范分别审计三个版本，修复确定问题，优化报告文字和图表，补分类与来源附注。已完成包只处理真实差异，不从头重做。
3. 用当前真实计分器与报告消费者做必要的精确工具验证，复用输入相同的合格证据。不要逐工具运行全库扫描/构建/四入口浏览器验收。新插件或共享代码改变时仅补直接受影响检查。
4. 在实际批准范围内提交/推送，使用现有安装与发布操作，回读真实状态。若目标运行环境尚未加载该版本或权限/接口不可用，停在明确可移交状态；不擅改平台或部署。

## 批量与恢复

每个工具独立记录状态和回执，同 key/语言/版本但不同 hash 必须解决冲突，不后写覆盖。一个工具资料不足、失败或连接阻塞，不阻止其他安全独立项。写入结果不确定时先回读，不盲目再 apply。失败原件保留，只重做失败或输入改变的步骤。未执行写 NOT_RUN，未查询写 UNKNOWN，不用 PASS 代替未查。

输出简短批次总结、逐项三版本/修改/标签、证据与 Git 链接、实际系统回执、未完成项和下一步。Notion 是进度索引，不是另一套审批；不得只更新文档就称系统已入库。入公共库不等于自动向四入口所有人授权，更不等于自动发布实际问卷任务。
