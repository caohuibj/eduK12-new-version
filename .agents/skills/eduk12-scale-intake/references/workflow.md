# 量表 AI 审计、优化与公共库导入规范

版本：1.0.0，2026-10-28。唯一权威文本为本文件，Notion 与对话引用它，不维护第二份相互漂移的规范。维护时更新版本并记录本次执行实际采用的 Git SHA。首次核查基线：9801107019d51a4af7ddb651789b674867539d24；下文路径是导航线索，每次执行以实际 checkout 合同为准。

## 1. 输入补全与去重

- 最少材料：条目、名称/出处（自编则注明）、目标构念和对象；作答选项若有一起提供。完整成品包也接受。
- 来源、语言、译本、题数相近不等于同一量表。保留原始输入，按稳定 key、语言、精确版本及 hash 去重，并区分新工具/新语言/新版本。
- 既有量表优先核原作者题本、手册/开发论文、正式译本及计分。缺信息先公开检索并记录实际取得的来源；付费、无法访问、未取得全文如实说明，不用另一版代替而不记差异。
- 缺报告可直接生成；缺阈值可明确 none。缺计分时不能凭措辞猜反向、擅自相加或补造维度。若原规则确实找不到，暂停该工具的正式评分入库，输出具体缺项，继续其他工具。
- 自编条目可提出完整初步计分/参数/解释设计，标记“研究自编/初步方案”，与原版或标准化版本区分。重要语义不可确定时才问最小必要问题；不增普遍人工审校步骤。
- 只处理量表材料，不将受测者真实答卷、身份信息、凭据混进公开仓库或 Notion。

## 2. 三个独立版本的审计与优化

### C：题本与计分

检查题目完整性、顺序/key唯一、指导语/回忆时段、对象/人称/自评或他评、选项文字及数值映射、维度、正反向、总分/均分、条件分母、缺失/中断规则和合法范围。用真实样例验证方向与边界；样例选择按公式/分支需要，不机械规定数量。

文字纠错与易读化不能暗改构念、程度、时间窗或选项。原题文本和计分保持可追溯；题意、选项、时段、维度或计分改变是 C 新版本，不能冒称原量表已验证版本。没有材料依据的正确性不能由 AI 自信替代。

### P：常模、参考参数或阈值

检查参数所引用的 scoreKey、适用群体/年龄/语言、计分版本、样本来源、区间端点/包含性、覆盖/重叠、方向及单位。区分正式常模、研究切点、经验解释区间、纯描述性范围。

没有可靠常模/阈值可用现有合同的 referencePolicy=none（若当前 schema 支持）并在报告明确说明，不能为“完整”编造数值。经验区间须有明确设计依据并标为暂定，不冒充临床界限、群体百分位或已验证诊断。合适的后续数据校准计划是附注，不是本次内容入库自动门禁。

### R：报告文字、图表与解释规则

- 依真实维度与计分方向写“本次发现—如何理解—可尝试的行动—简短限制”。温暖、具体、普通读者可懂，专业细节与出处放补充区域。
- 指标引用必须存在；分数、区间、文字和图表一致。可配图，但不为每份量表强制造图或重复视觉审计。优先已支持的图表/资源格式。
- 无常模时可呈现真实分数及量尺范围，不能把量尺百分比叫百分位/能力值。没有依据不出同龄排名、诊断、就业/升学预测。
- 缺失保留 null，真实零分保留 0，有符号差值不裁零。沿用实际报告消费者的有效/受限/无效状态，未完成不伪报完整报告；受限状态的文字、图像和下载一致。
- 报告 payload 的文字、图表、指标标签或解释发生改变均更新 R；仅目录标签改变只更新目录版本，不牵连未变的 C/P。改善报告措辞/配图不改变计分含义；改解释规则还需核其参数引用。源引用、限制和授权披露保持，图片不能泄露不可展示的指标。

### 分类和附注（每项必做）

沿用当前目录稳定 key/受控词表：心理领域与构念、用途、对象/年龄、SELF/他评、语言、时长（估计须注明）、理论取向等。附注记录 commercial/noncommercial/unknown、是否需联系作者、已知许可范围、翻译关系和研究成熟度。

科研审查和版权联系不做新的软件资格门禁或自动宣称通过。未知权利如实写未知；附注不是许可，实际复制/公开分发仍须遵守适用权利与发布范围，不能把“网上有全文”标为可公开上传。可以先生成仅含元数据/链接的记录，受限原文不强行放 GitHub。不要让人工逐份点击成为正常 AI 流程。

## 3. 版本与最小技术验证

C/P/R 分开管理，目录标签按实际目录版本管理。记录本次实际组合及内容 hash；旧版本不可覆盖，旧报告不读最新版重算。若当前工具没有独立参数版本，用真实 none 状态，不造占位常模。

复用当前 onboarding validator、registry、scorer、report renderer：输入完备性→精确组合→代表答案的真实计分与报告消费。报告文字变量、区间端点、缺失和反向边界按实际风险覆盖；纯内容包不要求每个包一次四入口浏览器/并发/安装系统全验。新增计分插件或改共享 UI 才补其直接消费者，系统通用能力已有合格证据且输入不变则复用。

- src/modules/scale/onboarding/axis-snapshots.ts
- src/modules/scale/onboarding/instrument-registry.ts
- src/modules/scale/onboarding/status.ts

当前 package.json 有 scale:instruments:generate、scale:instruments:check、scale:onboarding:check、scale:qualification:check、scale:instrument:install、scale:instrument:publish。必须先读真实脚本参数和影响范围再调用，不能把本列表当可直接复制的 apply 命令。

特别注意：onboarding/qualification 的现有检查会扫描全库，不逐工具重复跑；audit-scale-candidate-structure.ts 含历史来源与 SPANE 特例，不是任意上传材料的通用准入器；Survey library-preflight 的 1–10 个版本只读预检不是批量安装，也不是所有源必走的三轴审核。

Notion/文件模板只是工作记录，不创建新的强制服务端 schema、资格框架或签名门禁。只有确定性重复工作无法用已有工具可靠完成时才加小型辅助脚本，不默认建批处理引擎。

## 4. 安装、公共发布与回读

执行前确定目标环境、实际已加载的代码/registry、合法操作身份、本批允许的 visibility/入口范围；沿当前既有授权机制执行。没有这些能力仍完成前面内容加工，记录待安装原因。生产部署、实际账号/组织授予、正式任务发布不从“处理量表”自动推导。

按当前工具合同：install dry-run→核本批精确身份/部署 revision/runtime policy→获准范围内 apply；publish preview→按当前 proofHash 与参数 apply→回读。预览/写入事务的动态再核保留，不另加一层内容审计。安装的 DRAFT/HIDDEN/ACTIVE deployment 不能写成 PUBLIC。公开发布不是四入口全部管理员已被分配，更不是每类用户均已验收。

每个工具使用既有幂等/版本冲突机制；重复输入已经成功则回读复用，不重复创建。超时/连接中断先查询目标与回执，确认未执行才重试。一个失败项不回滚其他独立成功项，也不伪称整个批次原子提交。

当前 School/Teacher 直接来源/作者编排优化正在独立功能线实施。未合并且未加载的能力不得写为当前可用；此工作流不替代该开发、不手工制造四份量表、不要求使用者包装后再内容审查。缺适配时将“内容已合格”和“目标入口尚待接线”分开，其他可执行步骤继续。

读回至少：工具及语言、实际 C/P/R 组合与 hash、scaleId/releaseId、安装/公开状态、目标环境、允许的入口范围、记录时间和真实错误。仅已验证数据库写入才标 installed/published。Git commit/push/merge、环境加载、安装、公开、分配、上线分别记。

## 5. 批次记录、Notion 和结束条件

每批使用模板，不要求用户填表。每工具 artifact 记录成品 instrumentVersion/sourcePath/sourceHash，parameters.references 记录全部实际 referenceVersion/hash（none 时空数组）。每次写操作追加 operationReceipts：operation、environment、exactInputHash、proofHash（如有）、status、evidencePath、readbackAt；未确定结果使用 UNCERTAIN，回读同一意图后再决定续办，不拿改变的输入重放旧 proof。保存处理范围、输入和 workflow SHA、每工具状态及证据指针，记录每次输入变化失效了哪些证据。

Notion 在用户指定或已核实的工具库父页内按稳定 key/语言/version 找已有记录再更新，保留用户编辑与共享权限。同一工具更新原记录，不因重试重复建页。写入后回读；失败记 pending，不阻塞独立内容处理。不把无法公开的原文、真实答卷或秘密放进记录。

批次结束时报告：已加工/未齐、已提交/推送、实际安装/发布、目标环境与回执、未完成原因。没有仓库权限时明确为可移交包；没有系统访问时明确为未安装。不要把结构校验称科学效度验证、临床适用证明或作者许可。

本规范可用于单项与批量，批量只共享公共检查和 I/O，不合并各工具的评分/许可/版本事实。后续新对话应读同一 Git 版本、输入与记录恢复，不依赖前一对话的记忆或 PASS 摘要。
